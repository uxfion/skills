issue：[`docs/issues/20261110-how-we-work.md`](../issues/20261110-how-we-work.md)；设计：[`docs/specs/20261110-how-we-work-spec.md`](../specs/20261110-how-we-work-spec.md)；材料和草稿：issue 旁的参考文件夹（先读其中的 `START-HERE.md`）。

## 用户的话

「开启无人值守」（2026-11-10，在把 how-we-work 的形状、无人值守、内容三段定完，通用块改到第三版、七份参考的草稿都回来之后）。这一轮没有另外交代任务和资源；照当天定的：目标是项目的目标，对话里的任务排第一。

## 目标

这件事的目标是 issue 开头那句：把用户和 agent 怎么一起做项目写成一份，各项目是它的实例，用户不用再把同一句话在每个项目重说。主线是把 how-we-work 这个 skill 做到用户可以检查、点头之后很快就能用上：文件齐、脚本能跑、测过、在各项目的副本上走通。

## 回来时要看到的

1. `how-we-work/` 这个 skill 在仓库里建好：`SKILL.md`、`common.md`、七份参考、同步脚本和它的测试；仓库的约定检查通过。没有安装，没有推送。
2. 通用块和七份参考照交叉审查的结果改完；写论文那份按"jbhi 只是参考"改薄。main agent 直接定掉的点列成一张短表。
3. 同步脚本在六个项目 `AGENTS.md` 的副本上跑过：块写进去了，块外的内容没动，再跑一次没有变化。
4. 六个项目各一份接入包（放在参考文件夹，不碰项目本身）：接入后的 `AGENTS.md` 长什么样（通用块加它自己的部分）、它自己的各类约定、哪些旧规则和记忆因为通用块已经有了而可以去掉、和现在比少了什么多了什么。用户说一句"接入 zym"就能照着做。
5. 一个没看过过程的 agent 拿真实情形试整套（通用块加参考）的结果，和照结果做的修改。
6. skills 仓库自己的规则和通用块说同一件事的几处（设计原则 §4–§6），各一份"原文、修改建议、中文、理由"，等用户一处一处看。
7. 一份零背景也能看懂的简报。

## 往前做的（按对这件事的用处排）

1. 改参考草稿和通用块（等交叉审查回来；回来前先写同步脚本的设计）。
2. 把 spec 补全（脚本的命令、块的标记、`SKILL.md`、各类指针），自己审一遍，再建 skill。
3. 六个项目的接入包（派 subagent，同时不超过 8 个，用会话的模型）。
4. 新 agent 试用整套。
5. 设计原则和通用块对齐的提议；README 里加这个 skill 的一行（草稿）；旧 issue `20260929-agent-instructions-reusable-memories-wontfix` 怎么关的提议。
6. 还有余力：把各份参考里只属于某个项目的内容，放进那个项目接入包里它自己的约定文件。
