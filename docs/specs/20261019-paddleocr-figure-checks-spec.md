# paddleocr：合图之后的核对，没把握的图交给 agent（设计）

来源：[issue 20261011-paddleocr-figures-still-incomplete](../issues/20261011-paddleocr-figures-still-incomplete.md) 和它的[可行性报告](../issues/20261011-paddleocr-figures-still-incomplete-reference/README.md)（阶段一到五）。合图本身的设计见 [20261009-paddleocr-figure-groups-spec.md](20261009-paddleocr-figure-groups-spec.md)，本设计不改它。

用户的决定：
- 10-12 选方案 G：「大部分没有问题的，就直接通过我们合并的方式解决了……那种困难的，你需要把它检测出来」；「怎么检测可能会出问题，这点非常重要」。
- 重点抓严重错误：「我们现在抓的是比较极端的、完全不对的情况」；缺一行这类小问题「如果能解决的话，也最好一并解决」。
- 10-19：「我整体希望一个比较通用的方法，而不是很专业、针对某一领域的或者修修补补的」；第二意见「用核心 + 两条的方案」；「稍微的增加给agent的工作量是允许的，因为宁可多做也不要漏掉」。
- 其余按报告第 8 节的推荐：用到时再判断，检测连小问题一起抓，第二意见的框只给报出的图存。brodeur 那几张缺两行标题的图按小问题算。

## 1. 目标

- 合图照旧出图，`FIGURES` 不变。
- 合图之后，对每个图注核对几件本该成立的事。核对不上的图报 `figure_check`，附原因、各个框和一张叠加图。
- 被报出的图，在 Markdown 里它的旁边加一行注释。过后只读 Markdown 的 agent 也知道这张图可疑。
- agent 在任务用到那张图时再看，判断沿用原裁剪还是换一个。
- 宁可多看，不要漏掉：严重错误要全部报出，好图多送一些给 agent 可以接受。

不做：自动改图，自动采用第二意见的框。

## 3. 设计

### 3.1 位置

合图之后单独一步“图的核对”，接在重新裁图、文字核对之后。它只读块记录、页面图、PDF 文字层和 plus-L 的整图框，只写三样东西：告警、`checks/` 里的叠加图、Markdown 里的注释。新解析和已有解析的升级（3.6）走同一个函数。

代码放在新模块 `scripts/figcheck.py`，由 `parse.py` 调用。第二意见和五条核对是纯函数，可以单独测；这一步出错不影响出图（3.5）。

### 3.2 第二意见：以图注为锚的 8 条规则

从每个图注出发往图的方向扩，碰到挡板就停，扩到的范围就是它认定的图。它只用来比较，不出图。参考实现是报告里的 `prototype/slim/region_slim8.py`（加上 `prototype/region.py` 里的文字层、墨迹函数）。

1. **按证据定角色**：依据按可信度排，PDF 文字层的字体字号 > 版面几何 > 整图框 > VL 标签。
   - 正文字体：全文 300 字符以上的 `text` 块里，最常用的（字号, 字体）组合，占这类块的 10% 以上、至少 2 块。
   - 页眉页脚类标签 → 杂项；图注 → 图注；表注 → 表注；`image`、`chart`、`seal` → 图内容；`doc_title`、`abstract` → 正文。
   - 有文字层的页：文字层字符不到块内文字 25% 的块，字是像素 → 图内容；`table` → 表格；正文字体、300 字符以上或标题标签 → 正文；正文字体的短块 → 弱；其他字体、300 字符以上的正文类标签 → 正文；其他字体的 `figure_title`、`vision_footnote` → 图内容；其他字体的正文类短块 → 弱；其余 → 不明。
   - 没有文字层的页（扫描件、截图）：只看几何和标签。`table` → 表格；正文类标签 300 字符以上 → 正文；`figure_title`、`vision_footnote` → 图内容；正文类短块 → 弱；其余 → 不明。
2. **认图注**：沿用 `is_caption`，加上内容是图注的标题块。
3. **从图注往外长，碰到挡板停**：
   - 每个图注先往上找，找不到再往下。种子：图注 12 行以内、和它左右重叠的图内容块或表格块。
   - 图内容和表格块：上下、左右都在 6 行以内就并进来，或者和已有成员同在一个整图框里。
   - 弱和不明的块：只在紧贴（2 行以内、一半以上宽度重叠）、80% 以上落在已有范围内、或同在一个整图框里时并进来。
   - 挡板：正文、别的图注、表注、杂项、已归别的图注的块、小节标题（第 8 条）、上下 4 行内有表注的表格。一个块正下方 6 行内有别的图注，它就归那张图。
4. **整图框**：plus-L 的 image、chart 框，不盖住正文、图注、表注面积的 20% 以上时有效。两个块各有 70% 以上落在同一个框里，就是同一张图。
5. **按墨迹定边界**：范围是图注和最近的挡板之间，最远到页眉页脚，或成员外 6 行。图的框 = 成员的框裁到范围内，再加上和成员相连（半行以内）的墨迹。墨迹指任一通道比 235 暗的像素；别的块的框不算。
6. **一个块只归一个图注**：已归某个图注的块，对别的图注是挡板。
7. **正文行**：有文字层时，从范围离图注最远的那条边往回看，正文字体、排满一栏宽 85% 以上、30 个字符以上的行，以及这种段落的最后一行，都是正文，范围的边移到它们里侧。第一行要在边内页高 12% 以内，之后每行和上一行相距 3 行以内。
   - 为什么：VL 画的图块有时包进了几行正文（最差 07）。只看块，第二意见会和合图错得一样。
8. **小节标题**：`paragraph_title` 块只有下面 3 行内、同一栏里紧跟正文，才是小节标题、才挡住。下面跟着图的，是图里的标题，照常扩过去。`doc_title` 按第 1 条已是正文。
   - 为什么：VL 常把图里的面板标题标成小节标题（wangKnowledgeGraph Fig. 4）。

常量：`ROW`（页高 0.75%）、`COVER` 0.7、`SWALLOW` 0.2、`LONG_TEXT` 300 沿用 `parse.py`；其余数字写成 `figcheck.py` 的常量，取值同上。膨胀和连通域用 cv2，不新增依赖。

### 3.3 五条核对

对每页每个图注，先定它的裁剪：和 `uncropped_figure` 用同一套归属，每个裁剪（`figure` 块，或没并进别的块的 `image`、`chart`）归给同栏、40% 页高以内最近的下方图注，下方没有就归上方的。没有裁剪的图注仍报 `uncropped_figure`，逻辑不变。有裁剪的图注逐条核对，任一条不成立就报 `figure_check`：

| 原因 | 什么时候报 | 实测例子 |
| --- | --- | --- |
| `split` | 一个图注归了 2 个以上裁剪；或者跨页：图注在页面上 1/3、本页没有裁剪归它，前一页以不归图注的裁剪结尾（和 `uncropped_figure` 的跨页例外同一判断），而这样的裁剪有 2 个以上 | gadd Fig. 6；跨页：liLargeLanguageModel 扩展图 8、9 |
| `two_figures` | 另一个图注或表注有一半以上落在它的裁剪里；或裁剪内的文字层有一行以 “Figure 3:”“Fig. 2.”“Table 1 \|” 这类图注开头；或裁剪正下方（没有就看正上方）有两个并排的图注。它自己的图注不算 | tam 那篇的 4 页：VL 把相邻两张图画成一个块 |
| `table` | 页上有表注，40% 页高内却没有表格块，而这个图注的裁剪就在它旁边：表格被画进了图块 | VILA-M3 Fig. 2 |
| `edge_cut` | 裁剪某一边有 3 个以上墨迹连通块，一部分在框内，一部分越出边 2 px 以上（只看边外 max(4 px, 0.6 行) 的一圈） | MINIM 扩展图 5 |
| `second_opinion` | 第二意见有框，且某一边和这个图注全部裁剪的并集相差超过 1 行（多出或少了都算） | AgentMD Fig. 1、TISA Fig. 2 |

- 阈值都是报告阶段四事先定好的。`two_figures` 是看了新一批结果才补的，跨页的 `split` 是新加的，第 7、8 条规则是事后加回的，三处都要在新一批论文上验证（第 5 节）。
- 没有文字层时，`two_figures` 只看图注块和并排，第二意见只用几何。
- 原型的 `two_figures` 没排除图注自己，实现时排除：图注在裁剪里，评分时不算错。
- 跨页的 `split` 也会报前一页本来就是几张没编号的小图的情况，按“宁可多看”接受。

### 3.4 输出

**告警**：每个图注最多一条，列出所有没通过的原因。

```json
{"code": "figure_check", "page": 16, "block": 189, "detail": "Figure 6. Part of preprocessed medical knowledge …",
 "reasons": ["second_opinion: its top edge is 11.5 rows below the crop's"],
 "crops": [{"n": 1, "block": 188, "bbox": [111, 129, 1109, 1182], "image": "imgs/p16_….jpg"}],
 "second_opinion": [111, 266, 1109, 1182],
 "overlay": "checks/p16_189.jpg", "region": […]}
```

- `reasons` 每条是“原因: 哪一边、差多少”。`second_opinion` 写清第二意见的边比裁剪多出或少了几行。
- `crops` 的编号和叠加图上的编号一致。跨页的 `split` 列的是前一页的裁剪。
- `second_opinion` 是第二意见的框，没有时不写。它只存在告警里，块记录不加字段。
- `region` 和其他单块告警一样，是图注的 PDF 坐标。
- `uncropped_figure` 告警也加上 `overlay`，第二意见有框时也加 `second_opinion`：它常常就是被读成文字或表格的那张图的位置。

**叠加图** `checks/p<页>_<图注 id>.jpg`：144 dpi 的页面图上画出
- 这个图注，蓝框；
- 本页每个裁剪，各用一种颜色，左上角标编号；
- 第二意见的框，绿色虚线。

框都画在真实边界外约 6 px，不压住内容。跨页的 `split` 画前一页。编号和分色是因为两个相邻、中间隔着图注的框，看起来像一个框。

**Markdown 注释**：每张报出的图写一次。告警里已有 `overlay` 的图，说明注释写过，不再写。
- `figure_check`：写在这张图第一个裁剪的图片行之前，例如 `<!-- figure_check: second_opinion: its top edge is 11.5 rows below the crop's; overlay checks/p16_189.jpg -->`。
- `uncropped_figure`：写在图注那一行之前，例如 `<!-- uncropped_figure: no crop beside this caption; overlay checks/p08_77.jpg -->`。
- 找图注那一行：在这一页（两个 `<!-- page N -->` 之间）找开头和图注前 30 个字符相同的行，比较时去掉 `**`、空白，不分大小写。
- 找不到那一行时（比如已被手动改过），写在这一页的 `<!-- page N -->` 之后，注释里带上图注开头。读 Markdown 的 agent 总能看到它。

**记录**：`parser` 里加 `"figure_check": {"version": 1}`。plus-L 没加载上、第二意见没用整图框时，加 `layout_error`。

### 3.5 运行

- 只在有图注的页上跑。
- plus-L 和图分组共用，整次运行只加载一次。图分组只在有 2 个以上图块的页上跑它，核对还要在有图注的页上跑。每页最多跑一次，两步共用结果。
- 文字层的字体字号用 pypdfium2 读。图片输入没有文字层，第二意见只用几何。
- 出错时：这份解析不加 `figure_check` 告警，不记 `parser.figure_check`，stderr 和摘要写明原因，下次运行再补。出图、文字核对的结果不受影响。
- 新增开销预计每篇几秒，验证时实测（第 5 节）。

### 3.6 已有解析的升级

和 regroup、recrop 一样，跳过时就地补做：
- **触发**：`parser` 里没有 `figure_check`。
- **页面图**：按 JSON 里的页面尺寸重新渲染，图片输入读原图。`--photo` 的页面图无法复现，不补做，摘要写明原因，要补就 `--force` 重新解析。
- **处理**：在 regroup、recrop、recheck 之后跑图的核对，写入告警、叠加图和 Markdown 注释。Markdown 其他行和此前的修订都保留。
- **结果**：摘要标 `"figures_checked": true`；没做时 `"figures_check"` 写原因。
- `FORMAT`、`FIGURES`、`CHECK` 都不变。
- 文字核对以后重跑时（`CHECK` 升级），`figure_check` 告警原样保留，`uncropped_figure` 重新算出后接回它的叠加图和第二意见框。重新算出的告警里有新的（没有 `overlay`），图的核对就给它补做叠加图和注释。
- 以后 `figure_check` 的版本升级时，已有解析怎么迁移由那次改动另定，这里不预先设计。

### 3.7 agent 怎么处理（SKILL.md）

- **第 1 步**：摘要的 `figures_checked` 写进完成条件的说明。
- **第 2 步**：`figure_check` 和 `uncropped_figure` 一样，留到第 3 步，不要求在核对阶段处理。
- **第 3 步**：任务用到的图带着 `figure_check` 或 `uncropped_figure` 时（Markdown 里有注释），都要看，不跳过：
  1. 打开叠加图，先单看编号的裁剪本身：这张图完整吗？有没有装进别的图、表格或正文？
  2. 再参考第二意见的框和原因。
  3. 没问题就沿用，把注释改成 `<!-- figure_check: crop checked, kept -->`。
  4. 有问题就换一个裁剪，照现有的裁图步骤：从第二意见的框开始，不合适就从 JSON 里的框开始。裁出来看过，调好边界，换掉图片行，注释改成 `<!-- from page image: figure cropped by hand -->`。第二意见的框不经看过不能直接用。
  5. `uncropped_figure` 的图是文字、Markdown 里已有时，注释改成 `<!-- uncropped_figure: checked, the text is in the Markdown -->`。
- 注释有三种状态：原样的 `figure_check: …` / `uncropped_figure: …` 是还没看；`checked …` 是看过、沿用；`from page image: …` 是换过。
- **报告**：分开列出换过的、看过沿用的、还没看的。

SKILL.md 的措辞实现时按 writing-for-agents 写。

### 3.8 不做

- 自动改图，或者在某些条件下自动采用第二意见的框。那是从侧门回到补规则。
- 解析时就让 agent 判断。
- 给没报出的图存第二意见的框。
- 一张图本身跨两页。
- 改进合图本身。
- 没有文字层时第二意见弱、送给 agent 的图多，这一点接受。

## 5. 验证

1. 单元测试全部通过。
2. **和实测对齐**：115 篇已有解析走升级路径（不重新解析）。
   - 实现和原型有几处不同：排除图注自己、cv2 代替 scipy、PaddleX 的渲染代替 pypdfium2、`is_table_caption` 代替原型的表注正则。所以不要求逐条相同。
   - 逐图注比对 `figure_check` 和阶段五的结果（`prototype/slim/edge_flags.tsv`，以及 `bigtest` 的表注、裁剪边、两图结果），列出每一处不同，说清原因。
   - 报出率直接按 `bigtest/graded_layer.tsv` 的逐图对错重算。标准：严重错误一张不少（138/138）；送给 agent 的好图和阶段五的 125 张相差在 10 张以内。
3. **旧解析升级**：带手动修订的旧解析，修订原样保留，注释只加一次，第二次运行不再改动；`--photo` 的旧解析写明原因。截图目录照常核对。
4. **agent 从判断到裁图**：从 115 篇的告警里抽 30 张（10 严重、8 小问题、12 好图），交给一个没有上下文的 agent，只照 SKILL.md 处理。它裁出的图再盲评。看三件事：严重错误改对了几张，好图沿用了几张，第二意见的框有多少能直接用。
5. **新一批论文盲评**：另挑没用过的论文 20 篇以上，多放扫描件和 Nature 扩展图（跨页）。
