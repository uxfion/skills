# paddleocr：合图之后的核对，没把握的图交给 agent（设计）

来源：[issue 20261011-paddleocr-figures-still-incomplete](../issues/20261011-paddleocr-figures-still-incomplete.md) 和它的[可行性报告](../issues/20261011-paddleocr-figures-still-incomplete-reference/README.md)（阶段一到五）。合图本身的设计见 [20261009-paddleocr-figure-groups-spec.md](20261009-paddleocr-figure-groups-spec.md)，本设计不改它。

用户的决定：
- 10-12 选方案 G：「大部分没有问题的，就直接通过我们合并的方式解决了……那种困难的，你需要把它检测出来」；「怎么检测可能会出问题，这点非常重要」。
- 重点抓严重错误：「我们现在抓的是比较极端的、完全不对的情况」；缺一行这类小问题「如果能解决的话，也最好一并解决」。
- 10-19：「我整体希望一个比较通用的方法，而不是很专业、针对某一领域的或者修修补补的」；第二意见「用核心 + 两条的方案」；「稍微的增加给agent的工作量是允许的，因为宁可多做也不要漏掉」。
- 其余按报告第 8 节的推荐：用到时再判断，检测连小问题一起抓，第二意见的框只给报出的图存。brodeur 那几张缺两行标题的图按小问题算。

## 1. 目标

- 合图照旧出图，`FIGURES` 不变。
- 合图之后，对每个图注核对几件本该成立的事。核对不上的图报 `figure_check`，附原因、各个框和一张叠加图。原来的 `uncropped_figure`（图注旁没有裁剪）并进来，成为它的一个原因。
- 被报出的图，在 Markdown 里它的旁边加一行注释。过后只读 Markdown 的 agent 也知道这张图可疑。
- agent 在任务用到那张图时再看，判断沿用原裁剪还是换一个。
- 宁可多看，不要漏掉：严重错误要全部报出，好图多送一些给 agent 可以接受。

不做：自动改图，自动采用第二意见的框。

## 3. 设计

### 3.1 位置

合图之后单独一步“图的核对”，接在重新裁图、文字核对之后。

- **图的告警全归它**：只有一种告警 `figure_check`。没有裁剪的判断从文字核对里搬过来，成为它的一个原因。
- **两步各管各的**：文字核对只重写文字的告警，图的核对只重写 `figure_check`，谁也不碰谁的。
- 它只读块记录、页面图、PDF 文字层和 plus-L 的整图框；只写告警、`checks/` 里的叠加图、Markdown 里的注释。
- 新解析和已有解析的升级（3.6）走同一个函数。
- 合图出错时照样核对：图没合上，正好按 `split` 报出来。

代码放在新模块 `scripts/figcheck.py`，由 `parse.py` 调用。第二意见和各项核对是纯函数，可以单独测；这一步出错不影响出图（3.5）。

### 3.2 第二意见：以图注为锚的 8 条规则

从每个图注出发往图的方向扩，碰到挡板就停，扩到的范围就是它认定的图。它只用来比较，不出图。

1. **按证据定角色**：每个块先定是正文、图注、表注、图内容、表格、杂项，还是证据不足的弱块、不明块。依据按可信度排：PDF 文字层的字体字号 > 版面几何 > 整图框 > VL 标签。比如文字层里没有字的块，字在像素里，是图内容；正文字体的长段落是正文。
2. **认图注**：`is_caption`，或者内容是图注的标题块。图的核对全程用这一个判断。
3. **从图注往外长，碰到挡板停**：先把所有图注都往上扩，扩不到的再往下。图内容和表格块离得近就并进来，弱块、不明块只在紧贴时并进来。挡板是正文、别的图注、表注、杂项、小节标题和带表注的表格。
4. **整图框**：plus-L 画的整图框里的块是同一张图，框盖住了正文或图注的除外。
5. **按墨迹定边界**：图的范围是成员加上和它们相连的墨迹，最远到最近的挡板。
6. **一个块只归一个图注**。
7. **正文行**：有文字层时，正文字体、排满一栏的行就是正文，哪怕 VL 把它画进了图块；范围的远端停在这些行里侧。
   - 为什么：VL 画的图块有时包进了几行正文（最差 07），只看块，第二意见会和合图错得一样。
8. **小节标题**：标题块下面紧跟正文，才是小节标题、才挡住；下面跟着图的，是图里的标题，照常扩过去。
   - 为什么：VL 常把图里的面板标题标成小节标题（wangKnowledgeGraph Fig. 4）。

每条用到的数和细节在附录。

### 3.3 核对

**图注和它的裁剪**：
- 图注用 3.2 第 2 条的判断。
- 裁剪是 `figure` 块，或没有 `merged_into` 的 `image`、`chart`。
- 每个裁剪归给和它左右重叠、40% 页高以内最近的下方图注，下方没有就归上方最近的。这是原来 `uncropped_figures` 的归属。

每个图注逐条核对，任一条不成立就报 `figure_check`，一个图注一条告警，列出所有原因：

| 原因 | 什么时候报 | 实测例子 |
| --- | --- | --- |
| `no_crop` | 没有裁剪归它。两种情况不报，沿用原来的例外：同一页另一个同图号的图注有裁剪（标题、图例分在图的两边）；图注在页面上 1/3，前一页以不归图注的裁剪结尾（图一页、图注下一页） | 新一批论文附录里的提示词图，84 张 |
| `split` | 归了 2 个以上裁剪；或者跨页：上面那种“前一页以不归图注的裁剪结尾”，而这样的裁剪有 2 个以上 | gadd Fig. 6；跨页：liLargeLanguageModel 扩展图 8、9 被拆成 26 块和 55 块 |
| `two_figures` | 它的某个裁剪里有另一个图注或表注；或者裁剪正下方并排两个图注或表注（正下方没有时看正上方） | tam 那篇的 4 页：VL 把相邻两张图画成一个块 |
| `table` | 有表注，旁边却没有表格块，而它的某个裁剪就挨着这个表注：表格被画进了图块 | VILA-M3 Fig. 2 |
| `edge_cut` | 裁剪的某条边切开了 3 处以上的字或线 | MINIM 扩展图 5 |
| `second_opinion` | 第二意见的范围和裁剪的某一边相差超过 1 行文字（多出或少了都算） | AgentMD Fig. 1、TISA Fig. 2 |

- `no_crop` 的图也附上第二意见的框（有的话）：它常常就是被读成文字或表格的那张图的位置。
- 跨页的 `split` 只给那一页最上面的图注报，列出前一页的那些裁剪。前一页本来就是几张没编号的小图时也会报，按“宁可多看”接受。
- 阈值都是报告阶段四事先定好的。`two_figures` 是看了新一批结果才补的，跨页的 `split` 是新加的，第二意见的第 7、8 条是事后加回的，三处都要在新一批论文上验证（第 5 节）。
- 没有文字层的页，`two_figures` 不看文字行，第二意见只用几何。`--photo` 的页面图经过纠偏，文字层对不上，同样处理。
- **拿不到页面图时**（旧的 `--photo` 解析无法重新渲染，或渲染出错），只做不用页面图的四条：`no_crop`、`split`、`two_figures`、`table`；不做 `edge_cut` 和第二意见，不画叠加图，记录里写明跳过了什么。

每条的精确定义在附录。

### 3.4 输出

**告警**：

```json
{"code": "figure_check", "page": 16, "block": 189, "detail": "Figure 6. Part of preprocessed medical knowledge …",
 "reasons": ["second_opinion: its top edge is 11.5 rows below the crop's"],
 "crops": [{"n": 1, "block": 188, "bbox": [111, 129, 1109, 1182], "image": "imgs/p16_….jpg"}],
 "second_opinion": [111, 266, 1109, 1182],
 "overlay": "checks/p16_189.jpg", "region": […]}
```

- `block` 是图注。`reasons` 每条是“原因: 哪一边、差多少”。
- `crops` 按 JSON 块的顺序编号，和叠加图上的编号一致。跨页的 `split` 列的是前一页的裁剪；`no_crop` 没有这一项。
- `second_opinion` 是第二意见的框，没有时不写。它只存在告警里，块记录不加字段。
- `region` 是图注的 PDF 坐标，和其他单块告警一样，由这一步自己算。

**叠加图** `checks/p<页>_<图注 id>.jpg`：144 dpi 的页面图上画出
- 这个图注，蓝框；
- 本页每个裁剪，各用一种颜色，左上角标编号；
- 第二意见的框，绿色虚线。

框都画在真实边界外约 6 px，不压住内容。跨页的 `split` 画前一页，文件名仍用图注所在的页。编号和分色，是因为两个相邻、中间隔着图注的框看起来像一个框。

**Markdown 注释**：
- 内容：原因，末尾方括号里是这条注释的标记和叠加图路径，例如 `<!-- figure_check: second_opinion: its top edge is 11.5 rows below the crop's [p16#189 checks/p16_189.jpg] -->`。`p16#189` 是图注所在的页和它的 id。
- 写在哪：按下面的顺序找，找到第一个就写在它前一行：
  1. 第一个裁剪的图片行（跨页的 `split` 在前一页）；
  2. 图注那一行：在这一页（两个 `<!-- page N -->` 之间）找开头和图注前 30 个字符相同的行，比较时去掉 `**`、空白，不分大小写；
  3. 都找不到（比如已被手动改过），写在这一页的 `<!-- page N -->` 之后，注释里带上图注开头。读 Markdown 的 agent 总能看到它。
- 写过没有，看 Markdown 而不看 JSON：整篇 Markdown 里已有带同一标记的注释（不管什么状态），就不再写。所以重跑不会重复，写了一半失败后重试也不会。
- 不再报的图：它还没看的注释删掉，看过的不动。
- 注释的三种状态，agent 只改开头、方括号原样留着（3.7）：
  - `figure_check: …`：还没看；
  - `figure kept: …`：看过，沿用；
  - `from page image: figure cropped by hand; …`：换过。

**记录**：`parser` 里加 `"figure_check": {"version": 1}`。
- 拿不到页面图、跳过了几条时，加 `skipped`，例如 `["edge_cut", "second_opinion"]`。
- plus-L 没加载上、第二意见没用整图框时，加 `layout_error`。plus-L 只在某一页失败时，这一页的第二意见不用整图框，stderr 说明，和图分组一样。

### 3.5 运行

- **什么时候跑**：新解析在文字核对之后；已有解析跳过时，`parser.figure_check` 没有或版本旧（3.6）。
- **每次都整篇重跑**：所有图注都核对，`figure_check` 告警整体换新；Markdown 注释按 3.4 补写、删除。
- **跑完才记** `parser.figure_check`：中途出错时它不在，下次运行再补。
- **plus-L**：和图分组共用，整次运行只加载一次。图分组只在有 2 个以上图块的页上跑它，核对还要在有图注的页上跑。结果按文档和页缓存，两步共用。
- **文字层**：字体字号用 pypdfium2 读。图片输入和 `--photo` 只用几何。
- **出错**：出图和文字核对的结果不受影响；stderr 和摘要的 `figures_check` 写明原因，新解析和跳过时都写。
- **开销**：预计每篇几秒，验证时实测（第 5 节）。

### 3.6 已有解析的升级

和 regroup、recrop 一样，跳过时就地做：
- **触发**：见 3.5。regroup 改了裁剪，写 JSON 时去掉 `parser.figure_check`，图的核对就跟着重跑。
- **顺序**：regroup、recrop、recheck 之后。
- **页面图**：按 JSON 里的页面尺寸重新渲染，图片输入读原图；旧的 `--photo` 解析拿不到，按 3.3 只做四条。
- **旧告警**：此前文字核对报的 `uncropped_figure`，这一步跑完后换成 `figure_check`。
- **结果**：摘要标 `"figures_checked": true`；没做成时 `"figures_check"` 写原因。
- Markdown 其他行和此前的修订都保留。
- `FORMAT`、`FIGURES`、`CHECK` 都不变：文字核对的结果除了少掉 `uncropped_figure`，没有别的变化，而它由图的核对接手。

### 3.7 agent 怎么处理（SKILL.md）

- **第 1 步**：摘要的 `figures_checked` 写进完成条件的说明。
- **第 2 步**：`figure_check` 留到第 3 步，不要求在核对阶段处理。
- **第 3 步**：任务用到的图，Markdown 里带着 `figure_check:` 注释时，都要看，不跳过：
  1. 打开叠加图，先单看编号的裁剪本身：这张图完整吗？有没有装进别的图、表格或正文？
  2. 再参考第二意见的框和原因。
  3. 没问题就沿用，把注释开头改成 `figure kept:`。
  4. 有问题就换一个裁剪，照现有的裁图步骤：从第二意见的框开始，不合适就从 JSON 里的框开始。裁出来看过，调好边界，换掉图片行（`no_crop` 的图加在图注前），注释开头改成 `from page image: figure cropped by hand;`。第二意见的框不经看过不能直接用。
  5. `no_crop` 的图是文字、Markdown 里已有、颜色和版式也不带额外信息时，注释开头改成 `figure kept: the text is in the Markdown;`。
  - 只改注释的开头，方括号留着，重跑核对时靠它认出这条注释。
- **报告**：分开列出换过的、看过沿用的、还没看的。

SKILL.md 的措辞实现时按 writing-for-agents 写。

### 3.8 不做

- 自动改图，或者在某些条件下自动采用第二意见的框。那是从侧门回到补规则。
- 解析时就让 agent 判断。
- 给没报出的图存第二意见的框。
- 一张图本身跨两页。
- 改进合图本身。
- 没有文字层时第二意见弱、送给 agent 的图多，这一点接受。

## 4. 改动

- `paddleocr/scripts/figcheck.py`（新）：第二意见、六个原因的核对、叠加图、Markdown 注释。

  - 文档字符串：告警表里 `uncropped_figure` 换成 `figure_check`，加 `checks/` 目录和 `figures_checked`。
- `paddleocr/tests/test_figcheck.py`（新）：
  - 第二意见的 8 条规则，各用构造的块和文字层测一个正例和一个反例，包括第 7、8 条的两个实测场景，以及先上后下的顺序；

- `paddleocr/SKILL.md`：第 1–3 步按 3.7 改；第 2 步的 `uncropped_figure` 换成 `figure_check`。

## 5. 验证

1. 单元测试全部通过。
2. **和实测对齐**：115 篇已有解析走升级路径（不重新解析）。
   - `no_crop` 应和原来的 `uncropped_figure` 逐条相同，只多出标题块图注没有裁剪的情况。
   - 其余原因，实现和原型有意不同的几处：`two_figures` 不算自己的图注；cv2 代替 scipy；墨迹用 PaddleX 渲染的页面图，原型用 pypdfium2 直接渲染；表注用 `is_table_caption`，原型用自己的正则。所以不要求逐条相同。
   - 逐图注比对和阶段五的结果（`prototype/slim/edge_flags.tsv`，以及 `bigtest` 的表注、裁剪边、两图结果），列出每一处不同，说清原因。

**第二意见**

- 输入：文档的 VL 块，不含合图生成的 `figure` 块，但含被并进去的成员。
- 第 1 条，角色：
  - 有没有文字层按页定：一页的文字层少于 50 个字符，算没有。
  - 字体字号：字号 = 字体字号 × 字符矩阵的缩放，取到 0.5 pt；字体名去掉子集前缀（`ABCDEF+`）；一个块的字体字号，取中心落在块里的字符中最多的那种。
  - 正文字体是一组：在 300 字符以上的 `text` 块里按块计数，占 10% 以上、至少 2 块的（字号, 字体）都算。
  - 先看标签：页眉页脚、页码、`aside_text` → 杂项；图注 → 图注；表注（`is_table_caption`）→ 表注；`image`、`chart`、`seal` → 图内容；`doc_title`、`abstract` → 正文。
  - 其余的块，在有文字层的页上依次判断：
    1. 块内文字去掉公式和标记后至少 3 个字符（表格至少按 20 算），文字层字符却不到它的 25%：字是像素 → 图内容；
    2. `table` → 表格；
    3. 正文字体：300 字符以上或标题标签 → 正文，否则 → 弱；
    4. 其他字体、300 字符以上的正文类标签 → 正文；
    5. `figure_title`、`vision_footnote` → 图内容；
    6. 正文类标签的短块 → 弱；
    7. 其余 → 不明。
  - 没有文字层的页只看标签和长度：`table` → 表格；正文类标签 300 字符以上 → 正文；`figure_title`、`vision_footnote` → 图内容；正文类短块 → 弱；其余 → 不明。
- 第 3 条，长：
  - 顺序：所有图注从上到下各往上扩一遍；没扩到东西的图注，再从上到下各往下扩一遍。
  - 种子：图注 12 行以内、和它左右重叠的图内容块或表格块。
  - 图内容和表格块：和已有成员的并集上下、左右都在 6 行以内，或者和某个成员同在一个整图框里，就并进来。
  - 弱和不明的块：紧贴并集（上下 2 行以内、自身一半以上宽度和它重叠）、80% 以上落在并集里、或和成员同在一个整图框里，才并进来。
  - 挡板：正文、别的图注、表注、杂项、已归别的图注的块、小节标题（第 8 条）、上下 4 行内有表注的表格。挡板在候选块和并集之间（上下方向，各放宽 1 行），并和两者都左右重叠时，候选块不并进来。
  - 一个块正下方 6 行内有别的图注、且那个图注和它重叠过半宽度，它就归那张图。
- 第 4 条，整图框：plus-L 的 image、chart 框，盖住任何正文、图注、表注面积的 20% 以上时作废。两个块各有 70% 以上落在同一个有效框里，就是同一张图。
- 第 5 条，边界：
  - 范围：左右取成员和图注的并集；上下从图注到最近的挡板（和这个左右范围重叠的），最远到页眉页脚（杂项块下沿在页高 15% 以内、上沿在 85% 以外），最远到成员外 6 行。
  - 图的框 = 成员的框裁到范围内，再加上和成员相连的墨迹。墨迹指任一通道比 235 暗的像素，别的块的框里的不算；相连指膨胀半行后连在一起。
- 第 7 条，正文行：
  - 栏宽：这一页正文块宽度的中位数，不超过范围的宽度。
  - 满行：排满栏宽 85% 以上、30 个字符以上；满行下面紧接着的、3 个字符以上的行是段落的最后一行。两种都是正文。
  - 从范围离图注最远的那条边往回看：第一行要在边内页高 12% 以内，之后每行和上一行相距 3 行以内；范围的边移到这些行的里侧。
  - 字符怎么分行、距离怎么量（字号用 pt，位置用页面图像素），照 `body_lines`。
- 第 8 条，小节标题：`paragraph_title` 块按第 1 条没成为正文时（不是正文字体，或这一页没有文字层），下面 3 行内、同一栏里紧跟正文才挡住。正文字体的标题按第 1 条是正文，总是挡住。

**核对**

- 同栏：左右有重叠。“附近”：同栏，上下间隔 0 到 40% 页高（`UNCROPPED_REACH`）。
- `no_crop` 的跨页例外：前一页有不归任何图注的裁剪，且其中至少一个下沿过了半页。
- 跨页的 `split`：同上的前一页，不归图注的裁剪有 2 个以上。这种图注不做其余几条。
- `two_figures`，对它的每个裁剪：
  - 另一个图注或表注有一半以上面积落在裁剪里；
  - 或者裁剪内的文字层（pdfium `get_text_bounded`）有一行以图注、表注开头：可带 Extended Data、Supplementary，编号后跟 `.`、`:`、`|`，图号和它自己的不同；
  - 或者裁剪正下方“附近”有两个图注或表注上下重叠、左右不重叠；正下方一个图注都没有时看正上方。
- `table`：表注（`is_table_caption`）“附近”没有表格块，而这个图注的某个裁剪在它“附近”。
- `edge_cut`：它所有裁剪的同一边加起来，有 3 个以上墨迹连通块（比 235 暗，8 连通）一部分在框内、一部分越出边 2 px 以上。只看边外 max(4 px, 0.6 行) 的一圈，且在这条边的长度范围内。
- `second_opinion`：第二意见有框，且某一边和这个图注全部裁剪的并集相差超过 1 行。
