# paddleocr：合图之后的核对，没把握的图交给 agent（设计）

来源：[issue 20261011-paddleocr-figures-still-incomplete](../issues/20261011-paddleocr-figures-still-incomplete.md) 和它的[可行性报告](../issues/20261011-paddleocr-figures-still-incomplete-reference/README.md)（阶段一到五）。合图本身的设计见 [20261009-paddleocr-figure-groups-spec.md](20261009-paddleocr-figure-groups-spec.md)，本设计不改它。

用户的决定：
- 10-12 选方案 G：「大部分没有问题的，就直接通过我们合并的方式解决了……那种困难的，你需要把它检测出来」；「怎么检测可能会出问题，这点非常重要」。
- 重点抓严重错误：「我们现在抓的是比较极端的、完全不对的情况」；缺一行这类小问题「如果能解决的话，也最好一并解决」。
- 10-19：「我整体希望一个比较通用的方法，而不是很专业、针对某一领域的或者修修补补的」；第二意见「用核心 + 两条的方案」；「稍微的增加给agent的工作量是允许的，因为宁可多做也不要漏掉」。
- 其余按报告第 8 节的推荐：用到时再判断，检测连小问题一起抓，第二意见的框只给报出的图存。brodeur 那几张缺两行标题的图按小问题算。

## 1. 目标

- 合图照旧出图，`FIGURES` 不变。
- 合图之后，对每个图注核对几件本该成立的事。核对不上的图报 `figure_check`，附原因、各个框和一张叠加图。
- 被报出的图，在 Markdown 里它的旁边加一行注释。过后只读 Markdown 的 agent 也知道这张图可疑。
- agent 在任务用到那张图时再看，判断沿用原裁剪还是换一个。
- 宁可多看，不要漏掉：严重错误要全部报出，好图多送一些给 agent 可以接受。

不做：自动改图，自动采用第二意见的框。

## 3. 设计

### 3.1 位置

合图之后单独一步“图的核对”，接在重新裁图、文字核对之后。它只读块记录、页面图、PDF 文字层和 plus-L 的整图框，只写三样东西：告警、`checks/` 里的叠加图、Markdown 里的注释。新解析和已有解析的升级（3.6）走同一个函数。

只在合图做过（`parser.figures` 已记）之后跑。合图出错的新解析先不核对，下次运行补做合图之后再核对。

代码放在新模块 `scripts/figcheck.py`，由 `parse.py` 调用。第二意见和五条核对是纯函数，可以单独测；这一步出错不影响出图（3.5）。

### 3.2 第二意见：以图注为锚的 8 条规则

从每个图注出发往图的方向扩，碰到挡板就停，扩到的范围就是它认定的图。它只用来比较，不出图。

输入：文档的 VL 块，不含合图生成的 `figure` 块，但含被并进去的成员；页面图；PDF 文字层（字符、字体、字号）；plus-L 的整图框。

下面写规则的意思和数。细节以参考实现为准：报告里 `prototype/slim/region_slim8.py` 的 `classify`、`page_floats`，以及它从 `prototype/region.py` 用到的 `Layer`、`style_of`、`body_lines`、`connected_ink`。有意不同的只有第 5 节第 2 条列出的几处。

1. **按证据定角色**：依据按可信度排，PDF 文字层的字体字号 > 版面几何 > 整图框 > VL 标签。
   - 有没有文字层按页定：一页的文字层少于 50 个字符，算没有。
   - 字体字号：字号 = 字体字号 × 字符矩阵的缩放，取到 0.5 pt；字体名去掉子集前缀（`ABCDEF+`）；一个块的字体字号，取中心落在块里的字符中最多的那种。
   - 正文字体是一组：在 300 字符以上的 `text` 块里按块计数，占 10% 以上、至少 2 块的（字号, 字体）都算。
   - 先看标签：页眉页脚、页码、`aside_text` → 杂项；图注（第 2 条）→ 图注；表注（`is_table_caption`）→ 表注；`image`、`chart`、`seal` → 图内容；`doc_title`、`abstract` → 正文。
   - 其余的块，在有文字层的页上依次判断：
     1. 块内文字去掉公式和标记后至少 3 个字符（表格至少按 20 算），文字层字符却不到它的 25%：字是像素 → 图内容；
     2. `table` → 表格；
     3. 正文字体：300 字符以上或标题标签 → 正文，否则 → 弱；
     4. 其他字体、300 字符以上的正文类标签 → 正文；
     5. `figure_title`、`vision_footnote` → 图内容；
     6. 正文类标签的短块 → 弱；
     7. 其余 → 不明。
   - 没有文字层的页（扫描件、截图）只看标签和长度：`table` → 表格；正文类标签 300 字符以上 → 正文；`figure_title`、`vision_footnote` → 图内容；正文类短块 → 弱；其余 → 不明。
2. **认图注**：`is_caption`，或者内容符合 `CAPTION_TEXT` 的标题块。3.3 的核对也用这同一个判断。
3. **从图注往外长，碰到挡板停**：
   - 顺序：所有图注从上到下各往上扩一遍；没扩到东西的图注，再从上到下各往下扩一遍。
   - 种子：图注 12 行以内、和它左右重叠的图内容块或表格块。
   - 图内容和表格块：和已有成员的并集上下、左右都在 6 行以内，或者和某个成员同在一个整图框里，就并进来。
   - 弱和不明的块：只在紧贴并集（上下 2 行以内、自身一半以上宽度和它重叠）、80% 以上落在并集里、或和成员同在一个整图框里时并进来。
   - 挡板：正文、别的图注、表注、杂项、已归别的图注的块、小节标题（第 8 条）、上下 4 行内有表注的表格。挡板在候选块和并集之间（上下方向，各放宽 1 行），并和两者都左右重叠时，候选块不并进来。
   - 一个块正下方 6 行内有别的图注、且和那个图注重叠过半宽度，它就归那张图。
4. **整图框**：plus-L 的 image、chart 框，不盖住任何正文、图注、表注面积的 20% 以上时有效。两个块各有 70% 以上落在同一个有效框里，就是同一张图。
5. **按墨迹定边界**：
   - 范围：左右取成员和图注的并集；上下从图注到最近的挡板（和这个左右范围重叠的），最远到页眉页脚（杂项块下沿在页高 15% 以内、上沿在 85% 以外），最远到成员外 6 行。
   - 图的框 = 成员的框裁到范围内，再加上和成员相连的墨迹。墨迹指任一通道比 235 暗的像素，别的块的框里的不算；相连指膨胀半行后连在一起。
6. **一个块只归一个图注**：已归某个图注的块，对别的图注是挡板。
7. **正文行**：有文字层时，范围离图注最远的那条边，往回看正文字体的文字行：
   - 栏宽：这一页正文块宽度的中位数，不超过范围的宽度。
   - 满行：排满栏宽 85% 以上、30 个字符以上；满行下面紧接着的、3 个字符以上的行是段落的最后一行。两种都是正文。
   - 第一行要在边内页高 12% 以内，之后每行和上一行相距 3 行以内；范围的边移到这些行的里侧。
   - 字符怎么分行、距离怎么量（字号用 pt，位置用页面图像素），照参考实现的 `body_lines`。
   - 为什么：VL 画的图块有时包进了几行正文（最差 07），只看块，第二意见会和合图错得一样。
8. **小节标题**：`paragraph_title` 块按第 1 条没成为正文时（不是正文字体，或这一页没有文字层），只有下面 3 行内、同一栏里紧跟正文，才是小节标题、才挡住；下面跟着图的，是图里的标题，照常扩过去。正文字体的标题按第 1 条是正文，总是挡住。
   - 为什么：VL 常把图里的面板标题标成小节标题（wangKnowledgeGraph Fig. 4）。

`ROW`（页高 0.75%）、`COVER` 0.7、`SWALLOW` 0.2、`LONG_TEXT` 300 沿用 `parse.py`；其余的数写成 `figcheck.py` 的常量。膨胀和连通域用 cv2，不新增依赖。

### 3.3 五条核对

**图注和它的裁剪**：
- 图注用 3.2 第 2 条的判断。
- 裁剪是 `figure` 块，或没有 `merged_into` 的 `image`、`chart`。
- 每个裁剪归给和它左右重叠、40% 页高以内最近的下方图注，下方没有就归上方最近的。这和 `uncropped_figures` 的归属相同，只是图注的判断多了标题块。
- 没有裁剪的图注照旧报 `uncropped_figure`，那段代码不变（标题块的图注没有裁剪时，和现在一样不报）。

有裁剪的图注逐条核对，任一条不成立就报 `figure_check`：

| 原因 | 什么时候报 | 实测例子 |
| --- | --- | --- |
| `split` | 一个图注归了 2 个以上裁剪 | gadd Fig. 6 |
| `two_figures` | 它的某个裁剪里：另一个图注或表注有一半以上面积落在里面；或文字层（pdfium `get_text_bounded`）有一行以图注、表注开头（可带 Extended Data、Supplementary，编号后跟 `.`、`:`、`\|`），图号和它自己的不同。或者某个裁剪正下方（同栏、0 到 40% 页高）有两个并排的图注或表注，即上下重叠、左右不重叠；正下方一个都没有时看正上方 | tam 那篇的 4 页：VL 把相邻两张图画成一个块 |
| `table` | 页上有表注，和它同栏、上下 40% 页高内没有表格块，而它的某个裁剪在这个范围内：表格被画进了图块 | VILA-M3 Fig. 2 |
| `edge_cut` | 它所有裁剪的同一边加起来，有 3 个以上墨迹连通块（比 235 暗，8 连通）一部分在框内、一部分越出边 2 px 以上。只看边外 max(4 px, 0.6 行) 的一圈，且在这条边的长度范围内 | MINIM 扩展图 5 |
| `second_opinion` | 第二意见有框，且某一边和这个图注全部裁剪的并集相差超过 1 行（多出或少了都算） | AgentMD Fig. 1、TISA Fig. 2 |

**跨页的 `split`**，给没有裁剪的图注：
- 条件：图注在页面上 1/3，本页没有裁剪归它；前一页不归任何图注的裁剪有 2 个以上，其中至少一个下沿过了半页。
- 只给这一页最上面的那个图注报，列出前一页的这些裁剪。这种图注不做其余四条。
- 例子：liLargeLanguageModel 扩展图 8、9 被拆成 26 块和 55 块。
- 前一页本来就是几张没编号的小图时也会报，按“宁可多看”接受。

说明：
- 阈值都是报告阶段四事先定好的。`two_figures` 是看了新一批结果才补的，跨页的 `split` 是新加的，第二意见的第 7、8 条是事后加回的，三处都要在新一批论文上验证（第 5 节）。
- 没有文字层的页，`two_figures` 不看文字行，第二意见只用几何。`--photo` 的页面图经过纠偏，文字层对不上，同样处理。

### 3.4 输出

**告警**：每个图注最多一条，列出所有没通过的原因。

```json
{"code": "figure_check", "page": 16, "block": 189, "detail": "Figure 6. Part of preprocessed medical knowledge …",
 "reasons": ["second_opinion: its top edge is 11.5 rows below the crop's"],
 "crops": [{"n": 1, "block": 188, "bbox": [111, 129, 1109, 1182], "image": "imgs/p16_….jpg"}],
 "second_opinion": [111, 266, 1109, 1182],
 "overlay": "checks/p16_189.jpg", "region": […]}
```

- `reasons` 每条是“原因: 哪一边、差多少”。
- `crops` 按 JSON 块的顺序编号，和叠加图上的编号一致。跨页的 `split` 列的是前一页的裁剪。
- `second_opinion` 是第二意见的框，没有时不写。它只存在告警里，块记录不加字段。
- `region` 是图注的 PDF 坐标，和其他单块告警一样，由这一步自己算（`run_checks` 只给它自己的告警加）。
- `uncropped_figure` 告警也加上 `overlay`，第二意见有框时也加 `second_opinion`：它常常就是被读成文字或表格的那张图的位置。

**叠加图** `checks/p<页>_<图注 id>.jpg`：144 dpi 的页面图上画出
- 这个图注，蓝框；
- 本页每个裁剪，各用一种颜色，左上角标编号；
- 第二意见的框，绿色虚线。

框都画在真实边界外约 6 px，不压住内容。跨页的 `split` 画前一页。编号和分色，是因为两个相邻、中间隔着图注的框看起来像一个框。

**Markdown 注释**：
- 内容：告警名、原因、叠加图路径，例如 `<!-- figure_check: second_opinion: its top edge is 11.5 rows below the crop's; overlay checks/p16_189.jpg -->`、`<!-- uncropped_figure: no crop beside this caption; overlay checks/p08_77.jpg -->`。
- 写在哪：按下面的顺序找，找到第一个就写在它前一行：
  1. 第一个裁剪的图片行（跨页的 `split` 在前一页）；
  2. 图注那一行：在这一页（两个 `<!-- page N -->` 之间）找开头和图注前 30 个字符相同的行，比较时去掉 `**`、空白，不分大小写；
  3. 都找不到（比如已被手动改过），写在这一页的 `<!-- page N -->` 之后，注释里带上图注开头。读 Markdown 的 agent 总能看到它。
- 写过没有，看 Markdown 而不看 JSON：这一页已有带同一叠加图路径的注释（不管什么状态），就不再写。所以重跑不会重复，写了一半失败后重试也不会。
- 不再报的图：它还没看的注释（开头仍是 `figure_check:` 或 `uncropped_figure:`）删掉，看过的不动。
- 注释的三种状态，agent 只改开头、后面原样留着（3.7）：
  - `figure_check: …` / `uncropped_figure: …`：还没看；
  - `figure kept: …`：看过，沿用；
  - `from page image: figure cropped by hand; …`：换过。

**记录**：`parser` 里加 `"figure_check": {"version": 1}`。plus-L 没加载上、第二意见没用整图框时，加 `layout_error`。plus-L 只在某一页失败时，这一页的第二意见不用整图框，stderr 说明，和图分组一样。

### 3.5 运行

- **什么时候跑**：新解析在文字核对之后；跳过时见 3.6。都要求 `parser.figures` 已记。
- **每次都整篇重跑**：所有图注都核对，`figure_check` 告警和 `uncropped_figure` 的叠加图字段整体换新；Markdown 注释按上面的规则补写、删除。开始前先去掉 `parser.figure_check`，跑完才写上：中途出错时它不在，下次运行再补。
- **plus-L**：和图分组共用，整次运行只加载一次。图分组只在有 2 个以上图块的页上跑它，核对还要在有图注的页上跑。结果按文档和页缓存，两步共用。
- **文字层**：字体字号用 pypdfium2 读。图片输入和 `--photo` 只用几何。
- **出错**：出图和文字核对的结果不受影响；stderr 和摘要的 `figures_check` 写明原因（新解析和跳过时都写）。
- **开销**：预计每篇几秒，验证时实测（第 5 节）。

### 3.6 已有解析的升级

和 regroup、recrop 一样，跳过时就地做：
- **触发**：`parser.figures` 已记，并且满足其一：没有 `parser.figure_check`；它的版本比现在的旧；这次运行做了 regroup 或 recheck。
  - 后一条是因为 regroup、recheck 会整体重写告警，图的核对要跟着重跑，把图的告警补回来。
- **顺序**：regroup、recrop、recheck 之后。
- **页面图**：按 JSON 里的页面尺寸重新渲染，图片输入读原图。
- **`--photo` 的旧解析**：页面图无法复现，图的核对跑不了，摘要写明原因，要补就 `--force` 重新解析。它已有的图的告警，在 recheck 之后原样接回。
- **结果**：摘要标 `"figures_checked": true`；没做成时 `"figures_check"` 写原因。
- Markdown 其他行和此前的修订都保留。
- `FORMAT`、`FIGURES`、`CHECK` 都不变。

### 3.7 agent 怎么处理（SKILL.md）

- **第 1 步**：摘要的 `figures_checked` 写进完成条件的说明。
- **第 2 步**：`figure_check` 和 `uncropped_figure` 一样，留到第 3 步，不要求在核对阶段处理。
- **第 3 步**：任务用到的图，Markdown 里带着 `figure_check:` 或 `uncropped_figure:` 注释时，都要看，不跳过：
  1. 打开叠加图，先单看编号的裁剪本身：这张图完整吗？有没有装进别的图、表格或正文？
  2. 再参考第二意见的框和原因。
  3. 没问题就沿用，把注释开头改成 `figure kept:`。
  4. 有问题就换一个裁剪，照现有的裁图步骤：从第二意见的框开始，不合适就从 JSON 里的框开始。裁出来看过，调好边界，换掉图片行，注释开头改成 `from page image: figure cropped by hand;`。第二意见的框不经看过不能直接用。
  5. `uncropped_figure` 的图是文字、Markdown 里已有时，注释开头改成 `figure kept: the text is in the Markdown;`。
  - 只改注释的开头，叠加图路径留着，重跑核对时靠它认出这条注释。
- **报告**：分开列出换过的、看过沿用的、还没看的。

SKILL.md 的措辞实现时按 writing-for-agents 写。

### 3.8 不做

- 自动改图，或者在某些条件下自动采用第二意见的框。那是从侧门回到补规则。
- 解析时就让 agent 判断。
- 给没报出的图存第二意见的框。
- 一张图本身跨两页。
- 改进合图本身。
- 没有文字层时第二意见弱、送给 agent 的图多，这一点接受。
