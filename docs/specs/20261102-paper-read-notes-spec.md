# paper-read：论文笔记和项目论文索引（设计）

> **实施完成（2026-11-03），冻结。** 现在的做法以 `paper-read/` 里的 skill 为准；还没在实际中跑过的流程见 issue [20261103-paper-read-flows-not-run.md](../issues/20261103-paper-read-flows-not-run.md)。依据是 issue [archive/20261028-paper-to-zotero-paper-notes-fixed.md](../issues/archive/20261028-paper-to-zotero-paper-notes-fixed.md) 的已定 1–50，括号里的"已定 n"指那里的条目。第一版经过三份审阅（忠于已定、技术、新 agent 能不能照着用，报告随 issue 关闭已删，处理结果记在 issue 第 70 条），本版按它们改过，又按用户 2026-11-02 定的已定 44–50 改过。本文取代 [20261031-paper-skills-script-agent-division-spec.md](20261031-paper-skills-script-agent-division-spec.md) §5 的 paper-read 初稿。§9 是审阅之后讨论里补定的几处；之后又按设计原则过了一遍，改了 8 处（报告随 issue 关闭已删，8 处都在本文里），用户让我自己权衡后改（issue 第 81 条）。

## 1. 要解决什么

agent 在任何项目、任何一次会话里用到一篇论文，都能很快拿到对的、能对照原文核对的答案，不用再从头读；读出来的东西只记一处，越用越全；项目根据论文做的决定，以后查得到为什么，论文事实改了也找得回受影响的决定。

调研看到的现场（issue"调研结果"）：同一篇论文在一个项目里被抄 5 到 10 处，数字越抄越走样；论文事实和项目判断写在同一行；每个项目好几套编号；手工维护的索引在四个项目里都过时了。

## 2. 两样东西，一个例子

- **论文笔记**：在 Zotero 里，挂在论文条目下，每篇一条，第一行是"论文笔记"。只写论文本身：原文里的事实（写出出处，§4），以及对论文的判断（结论站不站得住、还能往哪走，标明是判断）。不写任何项目（已定 1、2、31、32）。
- **项目的论文索引**：在项目里，默认 `research/paper-index.md`。每篇用到的论文一个标题行，下面每个决定一行：决定、依据的要点、推理写在哪份文档、日期（已定 39、40）。

**例子**：ceus 在考虑 T-CACE（`xiaoTCACETimeConditionedAutoregressive2026`）能不能作 B-only 方案。

1. ceus 的主 agent 取 T-CACE 的论文笔记，还没有。这篇对 ceus 要紧：期刊论文，方法和 ceus 的问题直接相关。所以它决定整篇精读（已定 37）。
2. 它派一个读论文的 subagent。subagent 通读全文，按 8 问一问一问地答，事实写出出处。它顺手把结构化包里标着没整理的地方对照 PDF 整理好。
   - Q3 里写：输入是平扫 MRI 和肿瘤 mask，并引 Algorithm 1 的原句（Algorithm 1, p.5）。
   - Q6 的"假设和局限"里写：方法依赖肿瘤 mask 作输入，全文没说测试时可以不用。
   - 这些讲的都是论文本身，笔记里不出现 ceus。
3. 脚本检查树上没有没答完的问题，每条引文确实出自这篇论文。通过后，笔记和整理好的包存回 Zotero。
4. ceus 要据此做决定。它先对照 PDF 核对 Q3 里那句，在笔记里标上"（已核对 Algorithm 1, p.5 · 2026-11-02）"（已定 41）。
5. ceus 的索引里加一行："没采用作 B-only 方案：方法的输入要有肿瘤 mask（论文笔记 Q3、Q6），ceus 只有 B 超 · research/23_…/README.md · 2026-11-02"。
6. 以后 diffusion 想知道 T-CACE 要什么输入，取笔记就拿到；想知道 ceus 为什么没用 T-CACE，看 ceus 的索引。

## 3. 怎么用

### 3.1 每次改笔记都走同一套

整篇精读、写回一处、升级、核对留痕、更正，改的都是同一条笔记，都按这四步走：

1. **取出**：`prepare_note.py --cite K -o <临时目录>`。它取出笔记（没有就新建一份空的，§4），以及这篇的结构化包和 PDF（§6.1）。临时目录是 agent 的临时目录：会话的 scratchpad 下新建的一个子目录，没有 scratchpad 就用 `${TMPDIR:-/tmp}` 下的，从不放进项目。每次改笔记新建一个；同一次改动里重跑 `prepare_note`（比如解析完 PDF 之后）用同一个。
2. **改**：整篇精读交给读论文的 subagent（§7）；其余的由主 agent 自己改。
3. **检查**：`check_note.py`（整篇精读加 `--full`，§6.2）和 `check_quotes.py`（§6.3），都要 `pass`。
4. **存**：`p2z.py note put <笔记文件> -i`。
   - 回 `version_conflict`：笔记在别处被改过。另取到一个新的临时目录，把这次的改动并进去，再检查、再存。不要取回原来的目录，那会覆盖这次的改动。
   - 回 `same_title`：别的会话同时新建了这篇的笔记。取出那条，把这次的内容并进去，再存。

**完成**：两个检查都 `pass`，`note put` 回 `ok`，或者回 `skipped`（Zotero 里已经是这份内容）。

**改笔记的规矩**（已定 5、38）：
- 改之前读完整条笔记。
- 每处改动都有论文原文的依据，写出出处（§4）。
- 别人写的内容，除非原文证明它错，否则保留；问题编号一旦写下就不改，新问题接着往后编号。一个问题后来发现问错了，编号和标题留着，写明原因，不删。
- 改过的地方写一句"（更正 日期：原写"…"，按 <依据和出处> 改）"，这句一直保留。

### 3.2 查一处

1. 取出笔记，看它答没答这个问题。答了，就用。要拿它做决定或写进稿件，先核对（§3.4）。
2. 没答，或者不够：读结构化包里相关的部分，要用的数字对照 PDF。
3. 查到的东西是否写回笔记：讲的是论文本身，**或者**别的项目读这篇也会想知道的，就写回笔记，挂在它所属的那一问下面（升级，已定 39）。只对本项目有用的细节，留在项目里（§3.4）。
4. 写回按 §3.1 存。笔记原来没有的，存的这份只含答了的那一问，不带空的 8 问（§9 第 5 条）。

**完成**：答案落在笔记或原文上；该写回的已经存进笔记。

### 3.3 整篇精读

**要不要精读**，由用 paper-read 的主 agent 判断（已定 30、35、37）：
- 对项目重要、有用的论文，整篇精读；
- 其余的，只查用得上的那一处；
- 会议和期刊的档次是判断依据之一；
- 入库时不批量读。

笔记已经读完的（`check_note --full` 为 `complete`），不重读；缺什么就按 §3.2 补什么。

**步骤**（主 agent）：

1. **取出**（§3.1 第 1 步）。
   - `prepare_note` 报 `no_package`，说明 PDF 还没解析：用 paddleocr 解析，`structured put` 存回，再重跑 `prepare_note`。装不了 paddleocr，就只读 PDF，并告诉用户要装什么。
   - 包里有未整理的问题（`open_findings` 不为 0）：交给读论文的 subagent 在精读时顺手整理（§7.2）。它本来就要对照 PDF 看这些地方，又带着上下文，不另派整理的 subagent（已定 46）。
2. **派读论文的 subagent**（§7）。
3. **检查**：`check_note.py --full` 和 `check_quotes.py`；包整理过的，`doc.py show` 要打印 `no open findings`。没过的话，把输出原样发回同一个 subagent：Claude Code 用 `SendMessage`；接不上时，另派一个，给同一份 brief 和这份笔记文件。subagent 回来后，在项目里跑一次 `git status`，它留下的文件清掉。
4. **处理回报**：回报存在临时目录的 `report.md` 里，照它处理。
   - PDF 和这篇对不上：停下，告诉用户；
   - 包整理过的：`structured put` 存回 Zotero（已定 46）；
   - subagent 报出的库里的问题（标签、字段不对）：主 agent 先读一下那个条目，确认属实，再按 p2z 的规矩直接改，汇报里列出；删除、合并条目先问用户。写 Zotero 只在主 agent 一处（已定 47）；
   - 标"要看别处"的问题：留着，用户问到时再说；
   - 项目的问题：subagent 在回报里答了，按 §3.2 第 3 步判断要不要写回笔记；
   - 做不完：照它说的缺什么补上，再发回，或者告诉用户。
5. **存**（§3.1 第 4 步）。
6. **旧笔记**：这篇在 Zotero 里还有别的笔记（§3.7），整篇精读完后，问用户要不要把它们移进回收站。
7. **要问用户的事攒在一起**：同时读好几篇时，`two_notes`、PDF 对不上、旧笔记要不要删，等这一批读完，合成一条消息问用户。

**完成**：§3.1 的完成条件，加上 `check_note --full` 为 `complete`。

### 3.4 项目用论文

- **核对跟着用走**（已定 41）：
  - 项目要拿笔记里的某条事实做决定、写进稿件，先对照 PDF 核对这一条，在笔记里标"（已核对 <出处> · 日期）"；
  - 同一条只留最近一次的标记；已经标过的，后来的项目不必再核；
  - 标记按 §3.1 写回。
- **项目统一用 Zotero 引用键指论文**（已定 44）：项目的文档、索引里提到库里的论文，都写它的引用键，搜得到。稿件例外：`\cite{…}` 照用稿件自己 bib 文件里的键。
- **写进项目的论文索引**：每个决定一行（§5）。
  - 讲项目的问题、对项目的帮助、实现细节，写在项目原本按主题组织的文档里，索引指过去；
  - 一句话说得完的，就写在索引那一行里；
  - 不按论文建项目笔记文件（已定 40）；
  - 只写本项目的索引。
- **论文事实被更正后回头看**：读笔记时，看到某处更正的日期比本项目依据它做的决定更新，就回头重判这个决定，改写索引那一行（已定 39）。

**完成**：用到的事实都核对过、标在笔记里；每个决定都在索引里有一行。

### 3.5 更正

- 按 §3.1 改，守那里的规矩。
- 更正可能动到某些项目的决定。更正的 agent 在给用户的汇报里写明改了哪篇的哪一问、改了什么；本项目的索引里有依据它的决定，就当场重判。别的项目不去写，由它们读笔记时自己回头看（§3.4）。

### 3.6 主题笔记

一个主题一条 Zotero 独立笔记，放进"主题笔记"分类。这个分类只放主题笔记，整理库时不动它。主题笔记和它涉及的论文互设"相关"（已定 15、16）。

格式以后按当时的任务定，现在只定三条规矩（已定 43）：

1. 围绕这个主题要回答的问题来写；
2. 每句话注明出自哪篇论文笔记的哪一问（引用键 + Qn）。某句话还没有论文笔记可依据，就先写进那篇的论文笔记；
3. 只写要点，出处和细节留在论文笔记里。

### 3.7 库里的旧笔记

- **原样不动。** 整篇精读某篇时，`prepare_note` 把这篇的其他笔记也取出来，当线索交给读论文的 subagent。核对过的、讲论文本身的内容，写进新的论文笔记（已定 42）。
- **讲稿件或项目的部分**：属于当前项目的，主 agent 写进本项目的索引；属于别的项目的，在汇报里告诉用户。
- **旧笔记只当线索，不当模板**：不照它的结构、格式和论述顺序写（已定 42；设计原则 §4 *Write from the task, not from an old document*）。
- **永远不动的**：用户自己写的笔记和高亮。
- **已经清掉的**：arXiv "Comment:" 说明、Better Notes 欢迎页和测试笔记，共 28 条，2026-11-02 移进了回收站。

## 4. 论文笔记的格式

在 Zotero 外面，笔记是一份 Markdown：`<临时目录>/<cite>.<PDF 标题>.note.md`，比如 `xiaoTCACETimeConditionedAutoregressive2026.Published-IEEE.note.md`。和 Zotero 里 HTML 之间的转换由 `p2z.py note` 负责（已定 29；拆分 spec 已定 23）。

**空笔记**（整篇精读新建时的样子）。只写回一处而新建的笔记，只有标题、"读的版本"那一段和答了的那一问：没有 `[待答]` 那段概括，也没有空的 8 问（§9 第 5 条）。

```markdown
---
parent: <引用键>
pdf: <PDF 标题>
---
# 论文笔记

[待答]

读的版本：<PDF 标题>

## Q1 这篇论文要解决什么问题，为什么重要？这是哪类论文？ [待答]

## Q2 之前的工作怎么做，缺在哪里？ [待答]

## Q3 论文如何解决这个问题？ [待答]

## Q4 创新点是什么？ [待答]

## Q5 做了哪些实验？ [待答]

## Q6 结论站得住吗？ [待答]

## Q7 有什么可以进一步探索的点？ [待答]

## Q8 总结一下论文的主要内容 [待答]
```

**一句话概括**是标题下的第一段，最后写，最先读，沿用现有 reading.md 的做法。

**读的版本**是第二段，元数据区的 `pdf` 也记一份（已定 49）：
- `prepare_note` 两处同时写，换版本时两处一起改，读的时候读正文。元数据区里自己加的字段现在存不进 Zotero，等 p2z 修（issue `archive/20261102-paper-to-zotero-note-front-matter-fields-fixed.md`），正文那份兜底；
- 出处里的页码都指这份 PDF，按 PDF 的页序从 1 数起，和结构化包里的 `<!-- page N -->` 一致；
- 以后写回时，`prepare_note` 照这一行取同一份 PDF；
- 换一份 PDF 读，两处都改，原来写的页码注明指哪份。

**8 问**（已定 33；措辞按 issue 第 48 条，第 5 问的补充按已定 37）：
1. 这篇论文要解决什么问题，为什么重要？这是哪类论文（新方法、数据集、理论、应用研究……）？
2. 之前的工作怎么做，缺在哪里？顺带记下值得追读的文献。
3. 论文如何解决这个问题？写直觉和理由；用一个具体例子走一遍"输入 → 处理 → 输出"；写核心公式。对着方法总览图走一遍，说清图里每个模块对应正文哪一段（已定 36）。
4. 创新点：论文声称做出了哪些贡献？和最接近的已有工作比，新在哪？是概念上的新，还是只是实现细节或数据集不同？
5. 做了哪些实验？
   - 每个实验写"要回答什么 → 怎么做 → 结果"。
   - 对比实验怎么设计：和谁比、为什么选它们、用什么数据和指标、设置是否一致。
   - 固定写五项，每项以加粗的词开头（已定 50）：**数据和划分**、**对比方法**、**指标**、**主要数字**（带表号）、**代码和数据**（是否公开）。
   - 支撑主要结论的表和图，各开一个子问题，写"要回答什么 → 怎么得到的（数据、设置、跑了几次、误差棒）→ 数字和要点"。数字对照 PDF 看；包里标着 `unchecked_table` 的表一定要看。其余图表一句话带过：展示了什么、和哪张表一致（已定 34、36）。
6. 结论站得住吗？
   - 固定答五项，每项以加粗的词开头（已定 50）：
     - **证据和范围**：每条声称有没有证据，范围说没说过头；
     - **提升从哪来**：消融，对比方法调得是否一样用心，是不是多用了数据或算力；
     - **统计**：跑了几次，误差棒是什么，差距是否超出噪声；
     - **前后矛盾**：正文说法和表图对不上的写在这里；
     - **假设和局限**：论文说了的，以及明显该说而没说的。
   - 再对照领域参考清单，只写用得上的（已定 34）。
   - Q5、Q6 的固定项，论文没讲的，照样写出加粗的词，后面写"论文没有说明"；这一项不适用的，写"不适用"和一句原因。脚本只查加粗的词在不在。
7. 有什么可以进一步探索的点？
8. 总结一下论文的主要内容：写成描述性的、作者也会认同的总结，只用前面的回答写，带一句这篇的意义。

**问题树**（已定 26、28）：
- 标题就是问题树：主干问题用 `##`，子问题用 `###`，再往下用 `####`。
- 状态写在标题末尾：待答、进行中、已答、论文没有说明、要看别处、等 Qn。
- 每块前面空一行。
- 核对、更正的标记只写在正文里，不进标题（已定 38）。
- 问题编号一旦写下就不改（§3.1）。

**证据**：
- **出处**：写出它在论文的哪里，比如章节、图或表，需要时加上页码，如（Sec. III-A）、（Table III, p.11）。讲全篇思路的，或指不出位置的，不写（已定 45）。
- 回答所依据的原句，照抄英文，后面可以跟出处；空一个 `>` 行，再写中文译文（已定 17；格式见 §9 第 3 条）。公式写成 `$x_{NC}$`，美元符号里不留空格：

  ```markdown
  > "Given a non-contrast liver MRI scan $x_{NC}$ and its corresponding tumor mask $x_{TM}$, our model simultaneously synthesizes three clinically relevant phases" (Sec. III-A, p.3)
  >
  > 给定平扫肝脏 MRI 和对应的肿瘤 mask，模型同时合成临床上相关的三个时相
  ```

- 引文是从表格或图里抄的，脚本在文字层里找不到。对照页面图像核对过之后，在引文那一行末尾标"（已核对 <出处> · 日期）"，意思和 §3.4 的标记一样：有人对照过 PDF（§9 第 7 条）。
- 推断标"（推断）"；论文以外的知识标"（论文外）"；论文没写的，写"论文没有说明"，不猜。
- 对论文的判断（Q6、Q7）照样写进笔记，标明是判断；项目的判断不写进笔记（已定 2、9、32）。

**语言**：中文正文，术语、方法名、指标名、数字保留英文（已定 17）。

**领域参考清单**（已定 34）。这是起点，读的时候发现别的该查的，也写上：
- ML：把猜测说成解释；定理是否真支撑主要结论；"人类水平"这类说法站不站得住。
- 医学影像：队列代表性、标注质量、是否按病人划分、统计检验、临床情境、域偏移和病理病例。
- 判断的分寸：没到 SOTA、没开源代码、老实写出来的局限，本身都不算失败。"没写"是事实，直接写；"可能不公平"是判断，要写明依据。

## 5. 项目论文索引的格式

```markdown
## xiaoTCACETimeConditionedAutoregressive2026 · T-CACE: A Time-Conditioned Autoregressive … Diagnosis（JBHI 2026）
- 没采用作 B-only 方案：方法的输入要有肿瘤 mask（论文笔记 Q3、Q6），ceus 只有 B 超 · research/23_…/README.md · 2026-11-02
- 借鉴期相 token + 连续时间编码的双条件写法（论文笔记 Q3） · research/… · 2026-11-02
```

- **位置**：默认 `research/paper-index.md`；项目已有自己的论文索引的，就用它（已定 39）。
- **标题行**：`引用键 · 论文名 · 简称（出处 年份）`，由 `index_heading.py` 从 Zotero 生成（§6.4），不手打。
  - 简称来自 `aka/` 标签，出处来自 `venue/` 标签（tagging.md）。
  - 哪些论文有简称，按 tagging.md 的 *Common name* 定，这里不转述（规则 2026-11-02 放宽过，见 issue [archive/20261102-paper-read-aka-wording-fixed.md](../issues/archive/20261102-paper-read-aka-wording-fixed.md)）。
- **每个决定一行**：`决定：依据的要点（论文笔记 Qn） · 推理所在的文档和小节 · 日期`。原因一句话说得完、没有另写推理的，省掉"文档和小节"这一项（已定 40）。
  - 用上的、评估过没采用的都记，原因写清（已定 12、13）；
  - 项目改了决定，就改这一行，经过留在项目的 git 历史里。
- **语言**：中文，用户复盘时要读。
- **查哪些项目用过某篇**：在各项目的索引里搜引用键。

## 6. 脚本

都放在 `paper-read/scripts/`，带 PEP 723 块，用 `uv run` 跑。脚本只做确定的事；拿不准的交给 agent，脚本把证据交出去（设计原则 §1）。读 Zotero 一律经 `p2z.py`。

### 6.1 `prepare_note.py --cite K -o <临时目录>`

- **笔记**：`p2z.py note take --cite K -o <临时目录>/notes/` 一次取出这篇的全部子笔记，每条一个文件，输出里带标题。
  - 标题是"论文笔记"的只有一条：改名成 `<cite>.<PDF 标题>.note.md`，PDF 标题取自正文"读的版本"那一行；
  - 没有：按 §4 新建空笔记，元数据区的 `pdf` 和正文"读的版本"都填 `structured take` 选中的那份 PDF；
  - 有两条：停下，报 `two_notes` 和两个 key。合并、删除哪一条要用户点头，所以这一步交给用户；
  - 其余标题的，是这篇的旧笔记，留在 `notes/` 里当线索（§3.7）。
- **包和 PDF**：`p2z.py structured take --cite K -o <临时目录>`，笔记里写了读的版本就加 `--title <那份>`。
  - 回 `package: null`：报 `no_package`，附上 PDF 的路径；
  - 同一次改动里重跑时会回 `already_taken`：从已有的文件补出路径。
- **副本**：在笔记旁边存一份取出时的副本 `<笔记文件>.taken`，给 `check_note` 核对问题编号。
- **输出**：一行 JSON，内容有：
  - 笔记、包、PDF 和旧笔记的路径；
  - `open_findings`：包里未整理的问题，按种类计数；
  - 题目、第一作者、年份、出处、DOI，给读论文的 subagent 核对 PDF 用。

### 6.2 `check_note.py <笔记文件> [--taken FILE] [--full]`

在现有脚本上改：

- **默认**：
  - 笔记里有的每个问题标题都以状态结尾，没有"待答""进行中""等 Qn"；
  - "读的版本"那一段在；它前面要是有一段概括，那一段不是 `[待答]`；
  - 取出时的副本 `.taken` 里有的每个问题编号，改完后都还在，少了的列进 `missing_numbers`。问题的文字可以改。
- **`--full`**，整篇精读用，再加三项：
  - Q1–Q8 都在，缺的列进 `missing_trunk`；
  - 一句话概括写了；
  - Q5、Q6 固定项开头的加粗的词都在，缺的列进 `missing_items`。
- **结果**：`complete` 或 `open`，附上没过的项。

### 6.3 `check_quotes.py <笔记文件> --pdf <PDF> [--package <包目录>]`

脚本只查一件事：每条引文确实出自这篇论文。出处写不写、写得对不对，它不管，由读论文的 subagent 自我复核、项目用到时核对（已定 48）。

- **找引文**：笔记里以 `> "` 开头、引号之后到行尾只有出处和核对标记的那一行，就是一条引文。一条引文写在一行里，不折行；引文里原有的双引号照抄。行内的引号、不在这个格式里的数字，脚本不管。
- **比对**：两边都化成同一种规范形式再比：
  - 只留字母和数字；挨着数字的标点留着，免得 1.25 和 12.5 混在一起；
  - 去掉 LaTeX 和 HTML；
  - 连字符两边都去掉；
  - 引文按 `…` 切成几段，几段按顺序都要找到；
  - 太短的片段（规范形式不到 20 个字符，这个数是我定的）报 `too_short`，不算找到。
- **查找顺序**：
  1. 先查整份 PDF 的文字层（poppler 的 `pdftotext -raw`；paper-fetch 本来就要 poppler，不是新装的），找到是 `ok`；
  2. PDF 里找不到、只在结构化包里有（先去掉 `<!-- … -->` 注释），是 `package_only`，常见于没有文字层的表；
  3. 哪儿都没有，是 `not_found`。
- **结果**：
  - 每条一个结果；
  - 整篇是 `pass` 还是 `open`：每条都是 `ok`，或者那一行带"（已核对 <出处> · 日期）"，就是 `pass`。
  - 读论文的 subagent 对 `package_only` 和 `not_found` 的那几条，对照页面图像核对，改对了就标上核对标记，再跑一遍。
- **实测**（技术审阅，T-CACE，按同一页比对）：只归一空白时，包里 69% 的句子能在 PDF 里找到；用规范形式能找到 93%。剩下找不到的，多是公式里上下标的顺序不同。

### 6.4 `index_heading.py --cite K [K…]`

- 经 `p2z.py read_library items --cite` 读出条目，每篇打印一行 §5 的标题行。
- **简称和出处**：`aka/` 和 `venue/` 标签可能有好几个，全部按标签名排序列出，不替用户挑。
- **年份**：取 `date` 的前四位。
- **没有 `aka/` 标签**：标题行里不写简称，照样打印。本来就没有通称的论文不硬加（用户 2026-11-02：「不要强制加上去，你可以不加的」）；有业内通称却没打的是漏打，读论文时发现了就按授权补上，在汇报里列出（§12 第 13 条）。

## 7. 读论文的 subagent

按交接标准（[20261101-skills-handoff-standard-spec.md](20261101-skills-handoff-standard-spec.md)），分两处写。

### 7.1 派发说明（写在 SKILL.md，给主 agent 看）

- **角色**：读论文的 subagent。一篇论文一个，同时最多 5 个（按用户定的规矩，读论文这类重活最多 5 个并行）。用会话本身的模型：Claude Code 里不写 `model`，Codex 用默认模型。已定 27 写的是 opus，按设计原则 §1 改成会话本身的模型，实质一样。
- **每次派发要填**：
  - brief 文件、笔记格式文件（`references/note-format.md`）、两个检查脚本，以及包里有未整理的问题时 paddleocr 的整理说明（`references/settle.md`）和 `doc.py` 的绝对路径；
  - `prepare_note` 输出里的笔记、包、PDF、旧笔记的路径；
  - 题目、第一作者、年份、出处、DOI；
  - 项目带来的问题：只写问题本身，不写项目背景。
- **交回什么、怎么查**：交回的是笔记文件，就地改好；包有未整理的问题的，还有整理好的包。主 agent 跑两个检查，包整理过的再看 `doc.py show` 是否 `no open findings`（§3.3 第 3 步）。
- **处理回报**：见 §3.3 第 4 步。
- **退回**：把检查的输出原样发回同一个 subagent。

### 7.2 brief 文件（`references/reading.md`，给 subagent 看）

- **目标**：把这篇论文读成它的论文笔记，答完 8 问，以及读的过程中长出来的子问题。笔记怎么写，看派发里给的 `note-format.md`，brief 里不重写一遍。
- **输入**：派发里给的路径和信息。
  - 动手前先对照 PDF 第 1 页核对题目和第一作者，对不上就停下回报（§9 第 4 条）。年份和出处可以不同，因为 arXiv 版和正式版的年份常常不一样。
  - 包里的 `<!-- open … -->` 是没核过的地方，`<!-- unresolved … -->` 是已知的错，`unchecked_table` 是没有文字层的表：这些地方都以 PDF 为准（已定 21；paddleocr SKILL.md 的读法说明）。
  - 包里有 `open` 的地方，读到时顺手照 paddleocr 的整理说明对照 PDF 改好，用 `doc.py commit` 记下（已定 46）。
  - 旧笔记只当线索，不当模板（已定 42）。
- **怎么读**（已定 20–25）：
  - 先通读全文。
  - 一次答一问，答完写进文件再答下一问；答每一问都可以读全文任何部分。
  - 回答会长出子问题：证据就在原文里的，当场去查，挂在所属那一问下面；要等后面某一问回答的，挂上"等 Qn"，到那一问时再答。不预先列一长串子问题。
  - 答完一问回头看：解决了哪些子问题、长出了哪些，有没有推翻前面的回答；推翻了就把那一问改回"进行中"去改。
  - 什么工具都可以用。
- **产物**：只改这一份笔记文件和这篇的包，笔记只写论文本身。
  - 笔记已经有的内容、标记和问题编号，按 §3.1 的规矩处理。
  - 项目带来的问题，答在回报里，不写进笔记；主 agent 判断要不要写回（§9 第 8 条）。
  - 草稿可以另建在同一个临时目录里。
  - 存进 Zotero 是主 agent 的事。
- **完成条件**：
  - `check_note.py --full` 为 `complete`，`check_quotes.py` 为 `pass`；包整理过的，`doc.py show` 打印 `no open findings`；
  - 然后自己复核一遍：把每一问的回答拆成一条条声称，逐条对照原文，改正后再交（已定 41）。
- **回报**：写成临时目录里的 `report.md`，交回时也说一遍。只报例外：
  - PDF 和题目对不上；
  - 包整理了什么（整理的记录里也有）；
  - 库里条目的问题：标签、字段不对的，写清哪篇、哪里、该改成什么，由主 agent 去改（已定 47）；
  - 标"要看别处"的问题；
  - 项目问题的答案（带出处）；
  - 自我复核改了哪几处（一句话一处）。
- **规矩**：
  - 上网（比如看代码仓库）时，一次一个请求，同一网站间隔几秒；碰到人机验证、403 或 429 就停下，写进回报（paper-fetch 的上网规矩）；
  - 自己读，不再派 subagent；
  - 不碰 git；
  - 做不完就说清试了什么、确定了什么、还缺什么，交回主 agent。

3. **引文的写法**（§4）：原句照抄英文、下面附中文是已定 17；格式是 `> "原句"` 一行，后面可以跟出处，空一个 `>` 行，再写中文。这是实测定的：这样往返 Zotero 不变形，直接换行两行会被并成一行。
4. **核对 PDF 是不是这篇，交给读论文的 subagent**（§7.2）：它本来就要读第 1 页。只核对题目和第一作者，因为 arXiv 版和正式版的年份常常不同。

6. **Q5、Q6 的固定几项以加粗的词开头**（§4）：已定 50。论文没讲的写"论文没有说明"，不适用的写"不适用"和原因。

8. **项目带来的问题，读论文的 subagent 在回报里答，不写进笔记**（§7.2）：笔记只写论文本身（已定 32、39）。

## 12. 实施中的修正（2026-11-02 起）

写脚本和测试时发现、按 advisor 审阅改的几处。都是让脚本少漏、少卡，没有改设计：

1. **笔记文件名用包文件夹的名字**（§4、§6.1）：`structured take` 起文件夹名时，PDF 标题会先处理成合法的文件名，所以笔记文件取它给出的文件夹名加 `.note.md`，不自己拼 `<cite>.<PDF 标题>`。
2. **`check_quotes` 多了一种结果 `unparsed`**（§6.3）：以 `> "` 或 `> “` 开头、却不合引文格式的行，算没过。这样一条引文不会因为写法不对而悄悄漏查。弯引号 `“…”` 也算引文。PDF 文字层取两份，`pdftotext` 默认模式一份、`-raw` 一份，在哪份里找到都算 `ok`。
3. **`no_package` 时笔记照样准备好**（§6.1）：输出带上笔记文件和 `.taken` 的路径。解析完重跑 `prepare_note` 时接着用这份笔记；装不了 paddleocr 时，可以只对着 PDF 读。
4. **`check_note` 默认多查一项：笔记里至少有一个问题**（§6.2）。查一处如果没有要写回的内容，就不会往 Zotero 存一条只有"读的版本"一行的空笔记。
5. **`prepare_note` 失败时，原样带出 p2z 的输出**（§6.1）。笔记里"读的版本"写的 PDF，如果在库里已经找不到这个标题（比如被改了名），输出里有 `no_such_title` 和库里现有的 PDF 标题，由 agent 判断是哪一份。
6. **库里现在没有标题为"论文笔记"的笔记**（2026-11-02 查了全部 157 条），所以不存在缺"读的版本"一行的旧论文笔记，`prepare_note` 不为这种情况另做处理。
7. **`prepare_note` 加 `--title <PDF 标题>`**（§6.1）：指定取这篇的哪一份 PDF，不用笔记里写的那份，也不用排第一的那份。用在两处：一是"读的版本"那份 PDF 在库里改了名（第 5 条）；二是 §4 说的换一份 PDF 读，这件事原来没有办法让脚本取另一份。用了 `--title`，笔记里"读的版本"的两处由 agent 按 §4 一起改。
8. **年份取日期里的四位年份，不取前四位**（§6.4，`prepare_note` 的 `paper` 一样）：Zotero 的日期字段按录入时的样子存，库里有 11 条是 "6/2016"、"Aug 2020" 这类写法。按前四位取，VDSR 的标题行成了"（CVPR 6/20）"。
9. **查一处新建的笔记，那一问编成所属主干下的子问题**（§3.2、§4）：比如 `### Q3.1`，不写主干标题 `## Q3`。要是编成 `## Q3 <这一问>`，以后整篇精读要加主干 Q3 时，编号就冲突了，违反"编号写下不改"。实测 VDSR 查一处时发现的，已写进 note-format.md。
10. **回报写在 subagent 的回复里，由主 agent 存成 `report.md`**（§3.3 第 4 步、§7.2）：实测时 Claude Code 不让 subagent 写回报文件。状态仍然存在文件里，只是换成主 agent 来写。
11. **问题标题里不写 TeX**（§4、§6.2）：Zotero 的标题不显示公式。实测 T-CACE 时，标题里的 `$\hat{y}_i^{cls}$ … $f_\theta$` 存进 Zotero 再取回来，变成了 HTML 的 `<h3>`，`check_note` 就看不见这一问了。改法：符号用 Unicode 写（ŷᵢ、fθ），公式放进回答；`check_note` 报出标题里的 `$`（`math_in_heading`），并且把取回来的 `<h3>…</h3>` 也当标题读。
12. **改了 paper-to-zotero 的一行代码**：`note put` 新建的笔记总是报 `readback_mismatch`。原因是 `note_md.to_note` 在没有编辑器外壳时，输出的 HTML 结尾多一个换行，Zotero 存的时候把它去掉了，读回逐字比较就对不上。改成不带结尾换行；p2z 有 3 个测试的期望值原来是照代码写的，按实测改了，p2z 测试全过。这是在别的 skill 里改的，没有另开 issue，随这次改动一起提交。
