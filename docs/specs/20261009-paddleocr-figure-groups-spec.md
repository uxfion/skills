# paddleocr：把拆碎的图合回整张（设计）

来源：[issue 20261007-paddleocr-figure-split-fixed](../issues/20261007-paddleocr-figure-split-fixed.md)。用户选了 issue 里推荐的方向，要求「从全局考虑设计一个比较合理优雅的，然后有兜底的」。

## 1. 目标

一张图在 Markdown 里只出现一次，是一张完整的裁剪：
- 主图、框架图不被拆开；
- 多面板的展示图合成一张；
- 解析时漏检的面板，只要被 plus-L 的整图框罩住，也能补回来。

文字识别仍由 PaddleOCR-VL-1.6 负责，不换流水线。

不能出现的情况：把两张不同的图并成一张，或者把正文包进图里。

## 2. 依据（实测，6 篇论文 108 页）

| 事实 | 来源 |
| --- | --- |
| VL-1.6 的版面模型 PP-DocLayoutV3 没有“整张图”这一类，多面板图按面板出框。6 篇论文共 201 个图块，实际约 73 张图。 | issue 复核 |
| PP-StructureV3 的版面模型 PP-DocLayout_plus-L，用它自己流水线的配置（image 阈值 0.5，image 类用 `large` 合并），多数图能出一个整图框。6 个典型案例里 5 个是一整块，TMI Fig. 5 被漏掉的面板也在框内。 | issue 横向实测 |
| plus-L 也有失手的时候：TMI Fig. 2 在 “Step 2” 小标题处断开；整图框得分不够时，子图照样各自出来（单独跑 PP-StructureV3 时，TMI Fig. 3 是 6 块）。plus-L 对渲染方式敏感：同一页按流水线的方式渲染后再跑，TMI Fig. 3 却得到一个整图框。所以必须用流水线自己的页面图来跑。 | 同上 |
| plus-L 是 `paddleocr` 环境里现成的模型，125 MB，PaddleX 首次使用时自动下载。用 `load_pipeline_config("PP-StructureV3")` 读它的官方配置。按流水线的渲染方式（pypdfium2，scale 2），预热后每页 0.05–0.08 s。 | 实测，`paddlex.inference.pipelines` |
| 流水线的页面图在 `res["doc_preprocessor_res"]["output_img"]`（BGR），块坐标就在这张图上。PaddleX 裁图就是按块框直接切。 | `paddleocr_vl/pipeline.py`、`result.py` |
| VL-1.6 的 `figure_title` 混着三种东西：图注（“Fig. 3 …”）、面板字母（“a”）、图内小标题（“Step 1: …”、“prompt: …”）。有的图注还会被标成 `text`，比如 Nature Extended Data Fig. 1。 | 实测输出 |
| 上游没有现成参数能合图；PaddleOCR #18081 里仓库协作者的建议是：拿到 JSON 后自行合并。 | issue 调研 |

## 3. 设计

### 3.1 位置：解析之后单独一步“图分组”

`parse.py` 照旧生成块和 Markdown，然后对有图块的页逐页做图分组，再做核对。图分组只读写三样东西：块记录（JSON 里的 `blocks`）、Markdown 文本、页面图。它不碰 PaddleOCR 的内部对象，所以新解析和已有解析的升级（3.5）走的是同一个函数。

### 3.2 规则

先给页面上的块分类：
- **图块**：标签为 `image`、`chart`。加了 `--charts` 时，chart 已经转成数据表，不参与分组。`header_image`、`footer_image`、`seal` 也不参与。
- **图注**：以 Fig. / Figure / Extended Data Fig. / Supplementary Fig. / 图 加编号开头的块。标签是 `figure_title` 时，满足这个开头就算；标签是 `text` 或 `vision_footnote` 时，编号后面还必须紧跟 `.`、`:` 或 `|`，因为 “Fig. 7 shows …” 是正文。
- **图注的续行**：和图注同一行、在它右边、自身不是图注的文字块（`text`、`figure_title` 或 `vision_footnote`）。Nature 的通栏图注排成两栏，右半栏会被标成 `text` 或 `figure_title`，它也是图注的一部分：算进图注的宽度，也算挡板，不当作图内小标题。并排两张图各自的图注不能互相当成续行。
- **面板字母**：一两个字母的 `figure_title`，比如 “a”、“(b)”。
- **图内小标题**：其余的 `figure_title`，比如 “Step 1: …”、“prompt: …”、“(a) in silico”。
- **挡板**：会把图隔开的块，包括图注及其续行、章节标题（`paragraph_title`、`doc_title`、`abstract`），以及 300 个字符以上的正文块。图里的短文字、图里的表格不算挡板。

分两级合并，结果取并集：

1. **整图框（主）**：在这一页的页面图上跑 plus-L，用 PP-StructureV3 的配置。plus-L 的每个 image 框或 chart 框 F，满足三个条件就合并：
   - 至少 2 个图块有 70% 以上的面积落在 F 里；
   - F 不盖住任何挡板面积的 20% 以上（F 盖住了图注，说明它框错了）；
   - F 紧下方（四行以内）没有并排的两个图注；有的话，说明它罩住了左右两张图。

   合并后，这些图块成为一张图，范围取 F 和它们的并集。解析时漏检的面板如果在 F 里，也就一起框进来了，例如 TMI Fig. 5。
2. **图注兜底**：单元指图块或上一级已合成的图。先给每个单元找它的图注：在它下方、离它最近的那个图注，要求单元宽度的一半以上落在图注宽度以内，而且两者之间不隔着挡板。归到同一个图注下的单元合成一张图，前提是合成范围不盖住任何挡板面积的 20% 以上。每个单元只归一个图注，所以不会把上下两张图串在一起。

   同一行的单元（上沿、下沿都对齐在两行以内，左右相邻、间隙不超过两行）共用紧贴在这一行下方（四行以内）的图注：行里有单元找到了它，其余单元找到的是更靠下的图注、或者没找到时，改归这个图注。TMI Fig. 4 是横跨整页的一排面板，图注只在左半边；没有这条时，右半边的面板会越过它、并进右栏 Fig. 6 的图注。并排两张图的图注在同一高度，谁也不比谁“更靠下”，不受影响。

   plus-L 对每个面板单独出框的图（Nature 的附图多是几个独立的 chart）、以及 plus-L 加载不了的情况，都由这一级接手。这一级按位置判断，不看阅读顺序，因为分栏排版下的阅读顺序靠不住。

合成之后，把紧贴着它（相距两行以内）的面板字母和图内小标题也框进裁剪范围，例如每张子图下面的 “(a) Original dataset image.”；扩进来后范围不得盖住挡板，否则这一块不扩。

两级共同的保证：
- 不跨页；
- 不跨图注：整图框盖住图注、或底下并排两个图注时作废；兜底那一级每个单元只归一个图注；
- 落在合成范围内的面板字母并入这张图；
- 图内小标题、图里的短文字和表格保持原样，在 Markdown 里照常出现。

阈值：

| 名称 | 取值 | 含义 |
| --- | --- | --- |
| `COVER` | 0.7 | 图块这么多面积在 F 里，才算 F 的成员 |
| `SWALLOW` | 0.2 | 合成范围最多盖住挡板这么多面积 |
| `ROW` | 页高的 0.75% | 两个块上沿差这么多以内，算同一行（144 dpi 的 Letter 页约 12 px）；按页高算，截图分辨率不同也适用 |
| `LONG_TEXT` | 300 字符 | 这么长的文字块是正文，不会是图的一部分 |

### 3.3 输出

**JSON**：每张合成图是一个新块，放在它的第一个成员之前：

```json
{"id": 412, "page": 7, "label": "figure", "text": "", "bbox": [98, 102, 1121, 419], "image": "imgs/p07_figure_box_98_102_1121_419.jpg", "by": "layout"}
```

- 成员图块和被并入的面板字母保持原样，各加 `merged_into: 412`。这和现有“内容移入了那个块”的含义一致。
- 成员各自的裁剪图保留，要看某个面板的细节时可以打开。
- `by` 记下是哪一级合的：`layout` 或 `caption`。
- 新 id 接在本文档最大 id 之后。

**Markdown**：
- 第一个成员的图片行换成整图；
- 其余成员的图片行删掉；
- 并入的面板字母在 Markdown 里各自生成单独一行（如 `a`），这些行也删掉。字母通常排在它那张图之前，所以删行范围从这张图第一个并入块（成员或字母）对应的行算起，到最后一个为止；
- 其他行一律不动，包括 `--figure-text` 识别出的图内文字、prompt 这类小标题，以及图注。

**裁剪**：从页面图按合成范围直接切，存成 JPG，命名方式同 PaddleOCR：`p<NN>_figure_box_<x1>_<y1>_<x2>_<y2>.jpg`。

**记录**：
- `parser` 里加 `"figures": {"version": 1, "layout_model": "PP-DocLayout_plus-L"}`。没有用上模型时，`layout_model` 记为 `null`：
  - 文档里没有需要它的页，就只记 `null`；
  - 有页需要它、但加载失败，只用了图注兜底，就另加 `layout_error` 写明原因。
  - 以后要给这类解析补做整图框分组，靠 `layout_error` 认出它们。
- 摘要的 `blocks` 计数里会出现 `figure`。

### 3.4 运行

- plus-L 在第一次需要时才加载，整次运行只加载一次，PaddleX 首次使用时自动下载。
- 只在至少有 2 个图块的页上跑，因为少于 2 个时没有东西可合。
- 加载失败（比如离线又没有缓存）时，stderr 打一行原因，整次运行只用图注兜底，不退出。

### 3.5 已有解析的升级

v1、v2 的解析结果不重新解析，跳过时就地升级，做法和现在的 recheck 一样：
- **触发**：记录里没有 `parser.figures`，也就是还没合并过的解析。以后规则再改、`FIGURES` 版本升级时，已合并过的解析怎么迁移，由那次改动另定；这里不预先设计。
- **页面图**：只重新渲染有图块的页。PDF 按 JSON 里记的页面尺寸，用 pypdfium2 重新渲染；图片输入直接读原图。
- **处理**：做图分组，就地改写 Markdown 的图片行（文件名唯一，其他内容和此前的修订都保留），重跑核对，写回 JSON。
- **结果**：摘要标 `"regrouped": true`。

不重新解析，是为了保住此前在 Markdown 里做的修订。图片输入如果在解析时被缩放过，原图要先缩放到 JSON 里记录的页面尺寸再裁。

例外：`--photo` 的解析，页面图经过了纠偏和矫正，无法复现，只能保持原样；这时摘要提示需要用 `--force` 重新解析。

`FORMAT` 不变，否则旧解析会被整篇重做，修订也会被覆盖。

### 3.6 与核对的关系

`figure` 加入 `FIGURE_LABELS`。核对时，合成范围内的图中文字照旧不算漏字。补回来的面板，其坐标轴、标签原先会被报成 `missing_text`，以后不会了。`CHECK` 不变：升级时本来就会重跑核对。

### 3.7 不做

- **跨页的图**：极少见，分组只在页内进行。
- **图注在图上方或旁边的版式**：兜底那一级只认图注在图下方，这类版式通常是合不上。
  - 但图注在上方时也可能错合。版面是“Fig. 3 图注、Fig. 3 的图、Fig. 4 的面板、Fig. 4 图注”时，Fig. 3 的图在 Fig. 4 图注正上方，中间没有挡板，会被并进 Fig. 4。
  - 语料里没有出现。如果以后遇到，候选的修法是：一个单元离上方图注明显比离下方图注近时，归上方那张图。
- **双栏图注的误判**：右栏的正文段落恰好和图注同一行开始时，会被当成图注续行，图注宽度被拉到整页。这时右栏图注正上方没有图注隔开的图块，可能被误合；长正文本身是挡板，能挡住大部分情况。
- **没有 plus-L 时补漏检面板**：只能靠整图框来补。图注兜底只合已有的图块，不往外扩，避免把旁边的东西包进来。
  - 因加载失败只用图注兜底的解析，以后模型能用了也不会自动重新分组（已记了 `parser.figures`）；`layout_error` 留给以后的迁移。
- **VL 没标成图块的部分**：分组只合 VL 标成 `image`/`chart` 的块，下面几种情况留给 VL 的版面模型，分组救不回来。留出复验的 122 张图里，这几种情况共 11 张：
  - 纯文字的图，例如提示词、模型输出示例：被标成正文，没有裁剪，但文字已转写在 Markdown 里。
  - 文字为主的图，例如病例文本加图标：只能裁到被标成图的那一部分。
  - 被识别成表格的图，例如热图网格，或带图像列的结果表。
  - 图内的面板标题（“3. Processing …”）被标成章节标题：它是挡板，整图会在那里断成两张。

## 4. 模拟结果

用原型按上述规则，在 VL-1.6 已有的 6 篇解析结果上离线跑一遍（plus-L 跑了全部 108 页）：

| 论文 | 原有图块 | 合并后 |
| --- | --- | --- |
| LDM | 12 | 10 |
| SDEdit | 54 | 35 |
| Nature | 87 | 12 |
| TUFFC | 15 | 9 |
| MICCAI | 4 | 4 |
| TMI | 29 | 8 |
| 合计 | 201 | 78（实际约 73 张图） |

只用图注兜底、不用 plus-L 时是 82（LDM 10、SDEdit 35、Nature 14、TUFFC 11、MICCAI 4、TMI 8），没有把 plus-L 分开的图并在一起（逐页比对：图注兜底的每一组都落在有 plus-L 时的同一张图里）。这是实现时补了“同一行共用图注”之后的数；原型阶段是 129。

视觉评估：6 篇里所有带图的页共 57 页，逐页画出合并结果核对过。红框是合成的图，橙框是原样保留的单块图，蓝框是图注。
- 主图和框架图：LDM Fig. 3、TMI Fig. 2、SDEdit Fig. 2、Nature Fig. 1、Nature Fig. 6 的流程图、Extended Data Fig. 6 的数据流程图，都是完整的一张。
- 展示图和多面板图：
  - TMI Fig. 3–6；
  - Nature Fig. 2–5，以及 Extended Data Fig. 1、2、3、5；
  - SDEdit Figure 15、16、23、28、29；
  - TUFFC Fig. 1、4、6。

  都合成了完整的一张，TMI Fig. 5 漏检的面板也补回来了。
- 没有错合：TMI 第 7 页三张图各自独立；SDEdit 第 28 页的 Figure 22 没被并进 Figure 23。

原型迭代中改过三处，都是看图发现的：
- 兜底从按阅读顺序改为按位置，并把双栏图注的右半栏算进图注宽度。Nature Fig. 5 和 Extended Data Fig. 2、3、5 原先只合了左栏。
- 图注只认 “Fig. N” 开头，图内小标题（“prompt: …”）不算图注。否则 Nature Extended Data Fig. 1 的整图框会因为“盖住图注”被丢弃。
- 合成范围扩到紧贴的面板字母和小标题。

评审后又改了两处：
- 整图框那一级也加上挡板检查，57 页结果不变；
- 去掉了“单个图块按整图框扩大”这条规则，它在语料里一次都没触发过。

自查时又改了三处，用构造的反例和 57 页的对比来验证：
- 整图框那一级防“罩住并排两张图”。
  - 先试过“框里每个图块各自找下方图注，不止一个就作废”，结果反而错合：TMI Fig. 4 是横跨整页的一排面板，图注很短、只在左半边，右半边的面板一路找到 Fig. 6 的图注，整图框被作废后又被兜底并进了 Fig. 6。
  - 改成只看“框紧下方有没有并排的两个图注”，57 页结果不变，构造的并排反例也正确拆开。
- 兜底那一级改成每个单元只归最近的一个图注；原先一个单元可能被上下两个图注同时认领。
- 图注续行排除本身就是图注的块。构造的反例里，并排两张图的图注被互相当成续行，导致两张图被合在一起。

此外构造了一个反例：两组图块之间夹着一段以 “Fig. 3 shows …” 开头的长正文，结果没有合并，符合预期。

仍不完美：本来就是单块的图不改动，裁剪范围沿用 VL 的框。例如 SDEdit Figure 20 是界面截图，顶上那行说明文字落在框外，但这行文字已经作为正文转写出来了。

**与设计的出入**（都已改回本文相应位置）：
- 双栏图注的右半栏有时被标成 `figure_title`，会被当成图内小标题，扩边时把整段图注扩进裁剪（Nature Fig. 1、2、6，Extended Data Fig. 2）。
  - 改为：图注同一行右边的块算图注的续行，既是挡板，也不参与扩边；扩边后如果盖住挡板，这一块就不扩。
  - 这是看实际裁剪图才发现的，第 4 节的框图核对看不出来。
- 只用图注兜底时，TMI Fig. 4 的右半排面板越过它自己的短图注，并进了 Fig. 6。
  - 改为：同一行的面板共用紧贴在下方的图注。
  - 修后，只用图注兜底在 6 篇上得到 82 个单元，每一组都落在有 plus-L 时的同一张图里。
- 分组本身抛异常时，新解析保留未分组的结果、下次补做，不让整篇变成 `parse_failed`；升级出错时原样保留，摘要 `regroup` 写明原因。
- `parser.figures` 加 `layout_error`，区分“模型加载失败”和“不需要模型”。

**验证**（第 6 节）：
1. 69 个单元测试通过。
2. 6 篇用 vLLM 后端重新解析：每页的分组和整图框与原型逐一相同（201→78）。从原样的页面图、流水线的页面图、升级时重新渲染的页面图，三条路径得到的 plus-L 结果一致。实际裁剪图逐张看过。
3. v2 旧解析就地升级：埋进去的手动修订原样保留，Markdown 的改动只有图片行和面板字母行；第二次运行不再改动。6 篇共 24 s。
4. 空的模型缓存加上屏蔽网络：7 s 后退回图注兜底，正常结束，并记下 `layout_error`。模型已在缓存时断网：正常加载。
5. 截图：旧的截图解析升级，和对截图目录重新解析，结果一致。
6. 留出复验 8 篇（181 页，122 张带图注的图）：
   - 期刊和版式：arXiv 单栏、Nature 正文和 Extended Data、ICLR、EMNLP、npj、iScience、GigaScience、JAMIA。
   - 结果：111 张完整，11 张有问题，原因都在 3.7 的“VL 没标成图块的部分”。没有错合，也没有吞进图注或正文。
