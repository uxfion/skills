## 0. 目的和范围

- **skill 是通用的**：把任意 PDF 或页面图片，转成 agent 能直接读、能核实的结构化版本：
  - 阅读顺序的文字、表格、公式、图片；
  - 每一处都标明页码和位置；
  - 对照原文核对过。

  这样 agent 不必再读 PDF。
- **当前的用途**：给 Zotero 里的论文各做一份结构化版本，供各个项目的 agent 查阅。以后还会处理别的 PDF 和图片。
- **本稿做两件事**：
  1. 把通用的部分抽出来，作为 skill 的核心；
  2. 把论文方向做好，放在核心之上的"论文约定"一层。

  幻灯片、表单这类非论文文档以后再逐步优化（§9）。

## 1. 四层边界

| 层 | 是什么 | 谁写 | 放在哪里 |
|---|---|---|---|
| 原始 | 模型的输出：PaddleOCR 的块，以及第二个版面模型的框 | 解析时写一次，之后不再改 | 记录 JSON：`blocks` 的原样值、`pages` 的版面框 |
| 通用加工 | 对**任何文档**都做的整理：续段、跨页表格、脚注、公式编号、图片合组、裁图、文字层核对 | skill 的代码 | 记录 JSON 的修改记录，标为 `auto:<步骤>` |
| 领域约定 | 某类文档才有的写法和检查。现在只有论文：图注和表注的编号写法、补充材料前缀、面板字母、图核对六条 | 约定表 + 对应代码；给 agent 看的写在 `references/papers.md` | 同上，标为 `auto:<步骤>`；只在文档里**确实出现**这些写法时才生效 |
| 精修 | agent 或你的判断：改字、改表、重裁、告警结论 | 核对子代理、读的人、你 | 记录 JSON 的修改记录，标为 `agent` / `user`，并写明原因 |

**规则**：
- **通用加工和领域约定只补充，不删除、不改写 OCR 识别出的内容和类型。** "这几块属于某张图"这类判断用标记表达：JSON 里记成员，md 里用注释包起来。只有精修层（agent / 你）会改内容，而且原始值始终留在 JSON 里。这条管的是我们自己的步骤；PaddleOCR 自己的整理（`restructure_pages` 合并跨页表格、重定标题层级）算作引擎结果的一部分，记成 `auto` 修改，这样原始值仍保持原样；
- 后一层只**追加**修改，不覆盖前一层；
- 任何一处内容，都能追溯到它来自哪一层、经过了哪些修改；
- 核心对任何文档都能运行；领域约定没有命中时，核心照样产出完整结果，只是少了那一层的增强。

## 2. 包的结构

```
<stem>/
├── <stem>.md      阅读面：由记录 JSON 生成
├── <stem>.json    记录：原始值 + 全部修改 + 图 + 告警
├── imgs/          md 里显示的图，PNG，300 dpi，从源文件裁
└── pages/         只有 --photo 才有：校正后的页面图，因为框就是量在这些图上的
```

- **源文件在包外，是唯一的权威**：一份 PDF，或一组图片，按 sha256 识别。
- **只读 md 和 imgs/ 不需要源文件。** 重新加工、核对、裁图时需要它；sha256 对不上就拒绝执行。
- **PaddleOCR 的这些输出一律不存**：它自己的 md、它裁的 JPG、版面可视化图、docx、它自己的版面框和置信度。标准是：后续加工不读的、能从留下的东西算回来的，都不存（§3.4）。

## 3. 记录 JSON

### 3.1 结构

```json
{
  "format": 3,
  "source": {"kind": "pdf", "file": "qiu….pdf", "path": "/…/qiu….pdf", "sha256": "…", "page_count": 14, "pages": [1, …, 14]},
  "run": {"engine": "PaddleOCR-VL-1.6", "paddleocr": "3.7.0", "backend": "vllm-server",
          "options": {"charts": false, "figure_text": false, "photo": false},
          "layout_model": {"name": "PP-DocLayout_plus-L", "settings": {…}}, "at": "2026-10-19T…",
          "versions": {"refine": 1, "checks": 5, "figures": 2, "conventions": 1}},
  "pages": [{"page": 4, "image_size": [1191, 1582], "scale": 2.0,
             "layout": [["image", 0.91, 58, 47, 511, 600], …], "coverage": 0.93}],
  "blocks": [
    {"id": "p4-19", "label": "text", "box": [74, 1302, 593, 1444],
     "text": "Fig. 1 | Overview of our main evaluation pipeline and results. …"},
    {"id": "p4-20", "label": "text", "box": [607, 1302, 1126, 1424], "text": "", "group": "p4-19"},

  "figures": [
    {"id": "p4-12", "image": "imgs/p4-12.png", "caption": "p4-19", "number": "Fig. 1",
     "inside": ["p4-2", "p4-4", "p4-5", "p4-7", "p4-8", "p4-10", "p4-11", "p4-13", "p4-15", "p4-16"],

       {"by": "auto:figures", "box": [121, 679, 1065, 1248], "members": ["p4-12", "p4-14", "p4-17", "p4-18"],
        "grouped_by": "caption"},
       {"by": "agent", "at": "…", "box": [121, 97, 1065, 1249],
        "members": ["p4-3", "p4-6", "p4-12", "p4-14", "p4-17", "p4-18"], "why": "a、b 两个面板没包进来"}]}
  ],
  "checks": "ok",
  "findings": [
    {"id": "missing_numbers@p13", "code": "missing_numbers", "page": 13, "items": ["2409"], "detail": "…",
     "status": "ok", "why": "参考文献里折行的 arXiv 号", "seen": ["2409"]},
    {"id": "table_mismatch@p3-39", "code": "table_mismatch", "page": 3, "block": "p3-39",
     "items": ["composera", "…"], "detail": "…", "status": "open"}
  ]
}
```

（坐标为示意。以上是实现后的实际结构，示例取自 Qiu 一文的真实运行。）

- **块的修改**有这几种字段，按顺序套用：
  - `text`：整段换成新文字，只用于 PaddleOCR 整理时改了内容（合并跨页表格时的前半张、去掉开头的 `#`）；
  - `was` / `now`：agent 或你的改动。记的是最小的改动片段，按词扩大到在原文里只出现一次（"0.91"、"DeepSeek-RI" 这样的整词在 HTML 和 LaTeX 里也不会被拆开）；
  - `level`：标题层级；`merged_into`：内容并进了哪一块；`deleted`：删除。
- **新增的块**用 `added` 记下谁加的、跟在哪一块后面、为什么，`text` 是加进来的文字，之后的修改照样记在 `changes` 里。
- **图的修改**：`box` + `members`（范围和包含的图片块）、`hidden`（隐藏）。
- **重新解析时没找到位置的修改**放在顶层的 `lost` 里，检查时生成 `stale_edit` 告警。

### 3.2 原始值 + 修改记录

- **原始值原样保存**：每个块的 `label`、`text`、`box` 都是 PaddleOCR 给的值，从不改写。
- **修改按先后顺序追加**：每条修改记谁改的（`auto:<步骤>` / `agent` / `user`）、改了什么、为什么。块的当前内容 = 原始值，依次套上所有修改。
- **PaddleOCR 整理时做的改动也记成修改**，比如合并跨页表格、重定标题层级，都记为 `auto`。它还会去掉内容开头的 `#`（`pipeline.py:1281`），但实测两页的输出里没有出现过这种情况，只在真的改了时才记。这样生成 md 只看这份 JSON，不需要再调用 PaddleOCR 的内部函数。
- **代码改进以后重新加工**：
  1. 去掉所有 `auto` 记录，用新代码重新跑一遍；
  2. 把 `agent` / `user` 的修改依次套回去，按"块编号 + 当时改的那段原文（`was`）"对位置；
  3. 对不上的不会悄悄丢掉，而是生成一条 `stale_edit@<编号>` 告警，交给核对的人处理。

### 3.3 编号和坐标

- **块编号**：`p<页>-<block_id>`，例如 `p4-19`。`block_id` 是 PaddleOCR 自己的块序号，即该页列表里的位置：从 0 数，按它的阅读顺序，页眉、页脚、页码也算在内（`result.py:396`）。这个写法同时能当文件名用。
- **图编号**：这张图**第一次生成时**第一个图片块的编号，比如 `p4-12`。之后 agent 重裁、补成员，编号都不变。有图注和没图注的图都按这条规则。
  - md 里显示的每一张图片都是一张图：没有和别的块合组的图片块自成一图，编号就是它自己的块编号。
  - 重新加工时图沿用原来的编号：有人改过的图的编号优先，其次是它原来的编号，最后才取第一个图片块的编号。
- **唯一性**：一份记录里每个编号只指一样东西。
  - PaddleOCR 的块编号来自原始层，原始层不改，所以块编号永远不会重排，也不会被重复使用。被 agent 删掉的块保留编号，只标记为删除。
  - 新增的东西用带 `n` 的新编号，不占用 PaddleOCR 的编号：agent 补进来的块，比如漏掉的一行，编号为 `p9-n1`；没有任何图片块可以作锚的图，比如被读成文字的图、被拆开的两张图里的第二张，编号为 `p4-n2`。
  - 跨页表格的续表块保留自己的编号，只记"并入 `p4-39`"。
  - 表格里嵌的小图不算块，编号为所在表格块编号加序号，比如 `p6-14-1`。
  - 重新解析会产生新的原始层，编号以新的为准；旧的修改按"位置 + 原文"重新对上（§3.2）。
- **图号**：论文约定从图注里认出的 "Fig. 1"、"Supplementary Fig. 2" 记在 `number` 里，只写进 md 图片行的说明文字，方便搜索，不当身份。认图号沿用现有的图注配对做法，不新增处理。
- **告警编号**：`<代码>@<对象>`，对象是块、页或整篇，例如 `table_mismatch@p3-39`、`missing_text@p3`、`no_text_layer`。
- **坐标**：记录里统一用引擎页面图的像素，也就是 PaddleOCR 给的原样值；每页记下换算到源文件单位的比例 `scale`。
  - 脚本对外一律用源文件的单位：PDF 用点，图片用原图像素。`show` 打印的坐标、裁图命令接收的框，都是这个单位，可以直接用于 `pdftotext`，不用再换算。
  - `--photo` 例外：框量在校正后的页面图上，和 PDF 的点之间不是一个比例就能换算的。所以对外用 `pages/` 里校正后页面图的像素，裁图也从这些图裁。

### 3.4 原始层保留什么

标准：**后续加工会读到的模型输出**。存下来是为了让同一份输入始终得到同样的结果，并且重新加工时不用再跑任何模型。

| 模型输出 | 保留 | 理由 |
|---|---|---|
| 块：类型、文字、框、分组（`group_id`，只在不等于自己时记） | 留 | 一切的起点；分组用来区分"文字被并进了别的块"和"真的漏了" |
| 块的多边形 | 只在不是矩形时留 | 论文里都是矩形，等于框的四个角 |
| 第二个版面模型的框和置信度 | 留 | 图片合组和图核对要读。它其实能重新算（CPU 上 0.24 秒一页），存下来是为了结果固定、重新加工时不用加载模型 |
| PaddleOCR 自己的版面框和置信度 | 不留 | 后续加工不读 |
| `block_order`、页序号、临时路径、每页重复的模型设置 | 不留 | 能推算出来，或者没有意义；模型设置在 `run` 里记一次 |
| PaddleOCR 的 md、JPG、可视化图、docx | 不留 | 都能从块和源文件重新生成 |

**同一份输入必须得到同样的结果。** 改进加工代码时，要在完全相同的输入上比较改进前后（图核对"严重错误 138 处全部标出"就是这样验证出来的）。重新解析并不保证结果完全一样：实测换一个后端，就有 2–6% 的块不一致。所以原始层不能删。

## 4. 通用加工的流程

分两段，都只用 CPU，每篇几秒：
- **加工**：原始层 → 带 `auto` 修改的记录 JSON。要用 paddleocr 的环境，因为第 1 步调用 `restructure_pages`；
- **生成**：记录 JSON → md 和图片，是普通的 Python，不依赖 PaddleOCR。块外面那层格式（标题的 `#`、表格去掉 `<html><body>`、公式编号贴成 `\tag*{}` 等）照抄 PaddleOCR 的逐类规则，测试在 PaddleOCR 环境里逐字比对，保证和它自己的输出一样。逐块生成，md 的每一段才知道来自哪一块，`commit` 才能把改动对回去。

`doc.py render` 两段都做，要 paddleocr 环境（会自动换进去）。`commit`、`show`、`figure` 只用到生成，普通的 `uv run` 就能跑。只读 md 的项目两段都不需要。

步骤名记在修改的 `by` 里：PaddleOCR 的整理记 `auto:restructure`，图片合组记 `auto:figures`。

1. **读原始层** → 调 `restructure_pages`：合并跨页表格、重定标题层级。实测可以直接吃保存下来的数据。有页码缺口（`--pages`）时插入空页，避免表格隔着缺口合并。
2. **块级整理**：
   - 续段（同组的块）；
   - 脚注挪到页末；
   - 公式编号贴到对应公式后面；
   - 页眉、页脚、页码不进正文。
3. **图片**：
   - 把图片、图表块按版面模型画的整图框和几何位置合成一张图；
   - 套上 agent 给的新框；
   - 图框里的其他块（图里的标题、文字）**原样保留**，类型和内容都不动，在 JSON 里记为这张图的 `inside`；
   - 从源文件按 300 dpi 裁成 PNG，文件名就是图的编号；表格里嵌的小图也裁出来，名为表格块编号加序号；
   - 文字层检查时把整张图的范围排除在外，面板之间图里的字不会被当成漏字（以前合成的图是一个块，现在图不是块，要单独传给检查）。
4. **套上精修**：`agent` / `user` 的修改，对不上的生成 `stale_edit` 告警。
5. **检查**：在加工后的结果上运行（§6）。
6. **生成 md**（§5）。先写图片，最后原子地写 md 和 JSON。

**领域约定的接口**：第 3、5 步会查一张"约定表"。表里有某种写法，就启用对应的增强（§7）；没有就跳过，结果照样完整。

## 5. 生成 md 的规则

- **第一行是清单**，key=value 格式，例如：
  `<!-- paddleocr render=3 source=qiu….pdf sha256=8cbad18a pages=1-12/12 checks=ok coverage=0.93 figures=12 figures_checked=12 open=2 unresolved=1 body=<正文哈希> -->`
  - 检查没跑成时写 `checks=skipped:…`，不会显示成"没有告警"；
  - `figures` / `figures_checked` 分开写，用来区分"图都查过了、没问题"和"这里的图没有适用的检查"（比如图没有图注，或已经由 agent 重裁过）；
  - `body` 是正文哈希，用来发现手改过的 md（§6）。
- `<!-- page N -->` 放在每页开头，用来按页引用。
- 公式是 LaTeX，带编号的写成 `\tag*{(n)}`；表格是 HTML。
- **图**：OCR 的块按原来的顺序和类型输出。合成后的图片放在第一个成员原来的位置；图的范围用一对注释包起来，图里的标题和文字原样留在里面。认出图号时写进说明文字，没认出时留空。例如：
  ```
  <!-- figure p4-12 (Fig. 1) -->
  ## a. Evaluation Framework
  ![Fig. 1](imgs/p4-12.png)
  Case summary: The patient feels stomach pain …
  …
  Treatment Planning
  <!-- end figure p4-12 -->

  Fig. 1 | Overview of our main evaluation pipeline and results …
  ```
  `SKILL.md` 里写明：`figure` 标记之间的标题和文字属于这张图，不是正文的章节。
  - 一张图除了图片本身什么都没有（只有一个图片块、范围里没有别的块）时，不加标记，只有图片行；图片文件名就是图的编号。
  - 夹在图的块中间、却不在图框里的正文块，排到结束标记之后，保持原来的相对顺序。
- **跨页表格**：合并后的表格后面写 `<!-- table p4-39 continues on page 5 -->`。这和论文无关，放在通用层（原 §7.2 第 2 条）。
- **注释**一律用英文，开头是固定前缀，并带告警编号：
  - `<!-- open table_mismatch@p3-39: … -->`：待核对。漏字的告警直接把文字层的原文放进注释。
  - `<!-- unresolved … -->`：核对过但改不了。
  - `<!-- fixed: <why> -->`：修正过，写原因。每个被 agent / 你改过的块、重裁过的图上方一条，几次修改的原因用分号连起来；没写原因就是 `<!-- fixed -->`。
  - 判为误报（`ok`）的告警不写进正文。
  - 告警注释放在它的块、图或页的前面；块没写进 md 的（并进了别的块的除外，它跟着目标块），放到该页末尾。

## 6. 核对（settle）

- **由谁做**：交给小一号的模型做子代理，最多五个同时跑。brief 是通用的 `references/settle.md`；论文的特殊情况看 `references/papers.md`。
- **告警状态**：
  - 修对了，下次检查时告警自然消失，不用另外记；
  - 需要记的只有 `ok`（对照原文后确认解析没问题，包括误报和"只能人工看"的那几类）和 `unresolved`（改不了），连同当时看到的条目 `items` 一起记；
  - 下次检查算出来的条目都在原来的范围内，就沿用结论；多了新条目，就重新打开；
  - 每次写入后，都打印哪些告警消失了、哪些是新的、哪些重新打开了。
- **修改方式：直接改 md，再提交**（用户选定）。
  - agent 用普通的编辑工具改 md，在修改处上方写 `<!-- fixed: … -->`；把注释开头的 `open` 改成 `ok` / `unresolved`，就算给出了结论。
  - 然后运行 `doc.py commit`：脚本知道每一块在 md 的第几行，把改动换算成块级修改，写进 JSON。
  - 任何 `doc.py` 命令运行前都会先提交 md 里尚未提交的改动，不会覆盖手改的内容。
  - 一处改动跨了好几块，比如重排段落：合并后的文字记在第一块，其余几块标记为删除。
  - 修改原因取自上方的 `<!-- fixed: … -->`；没写就记为空，照样提交，不拒绝。
  - 有几行受保护，改了 `commit` 会拒绝并说明原因：第一行清单、`<!-- page N -->`、`figure` 的包裹注释。
  - 手动删掉一行图片，表示隐藏这张图；`commit` 时会提示，重新裁图请用 `doc.py figure`。手动加的图片行会被拒绝。
  - 依据：示例六篇里的全部修正都是在 md 里直接改的，有改一个词、改表头拆格、补截断的结尾、重排跨块的段落，Sonnet 都改对了。
  - **实现的做法**：
    - 由记录重新生成 md，和 agent 改过的 md 按行比较。受保护的行把文件切成一段段，各段分别比；只比非空行，删掉注释留下的空行不会让行错位。
    - 一处改动涉及的块整块取出，在 md 片段上求最小改动；这个片段在块的原文里只出现一次，就直接记成 `was` / `now`；否则先按 PaddleOCR 的规则把 md 还原成块的内容（去掉标题的 `#`、公式后补上的 `\tag*{}` 等），再求最小改动。公式和贴在它后面的编号算一处：只改公式本身时编号块不动，改了编号就并进公式、编号块标记为删除。
    - 前后有空行的新段落成为新块（`p9-n1`），跟在前一块后面；不空行、直接接在段落后的一行并进那一段。
    - 告警的结论：把 `open` 改成 `ok` / `unresolved`，冒号后面写原因，原因和当时看到的条目一起记下。
    - 找不到源文件时，`commit` 照样记下改动，但不重跑检查，告警保持上次检查的结果。
    - 在六种改法（改词、改表格一格、改公式、改标题层级、插段落、跨块改）和受保护行上都测过，在 Qiu 一文上实测过改字和给结论。
- **只有裁图要用命令**：`doc.py figure <图编号> --box x1 y1 x2 y2`，框用源文件单位。命令会裁出新图并打印路径给 agent 看，新框记入 JSON。
- **`doc.py` 的命令**：
  - `render`：重新加工并生成 md；
  - `show`：只读。列出待核对告警；看某条告警或某一块，会给出原文、文字层片段、页面截图和标注图的路径；看某一页，会列出该页所有块；也可以按指定 dpi 现裁一张图看细节；
  - `commit`：提交 md 里的改动；
  - `figure`：重新裁图。
- **写入防护**：
  - 锁文件独占创建，里面记 pid 和时间，过期的锁可以接管；
  - 先写临时文件再改名；
  - md 正文哈希对不上时，先提交改动，再生成。

## 7. 论文方向

### 7.1 约定表

约定表是数据，放在 `scripts/conventions.py`，可以随时增改，不是封闭的清单。

- **图注写法**：`Fig.`、`Figure`、`图`；前缀 `Extended Data`、`Supplementary`。
- **表注写法**：`Table`、`表`，罗马数字编号。
- **面板字母**：`a`、`(b)`、`C.` 等。
- **公式编号**：`(n)`，也认全角括号 `（n）`（模型有时这样读）；公式里的 `\tag{n}`、`\tag*{(n)}` 也算编号。

现在这些写法写死在 `parse.py:755–760` 和 `figcheck.py` 里，要搬到约定表。

### 7.2 论文专有的加工

都只在命中约定时才做：

1. **图号**：沿用现有的图注配对做法认出图号（"Fig. 1"、"Supplementary Fig. 2"），记在 `number` 里，写进 md 图片行的说明文字。语料里带编号的图注有 2323 个，编号重复的 18 个；表注 1849 个，重复 60 个。图注本身是哪一块、图里的文字是什么，都不另做判断，按 OCR 原样输出。
2. ~~跨页表格~~：挪到了通用层（§5），因为它和论文的写法无关。
3. **公式编号**：语料里 1550 个行间公式，单独的编号块只有 745 个。生成 md 时把编号贴成 `\tag*{(n)}`。

### 7.3 论文专有的检查

- **图核对六条**：没有裁剪、被拆成几块、一块里有两张图、把表画进了图、边缘切到字、和第二意见不一致。这些继续以图注为起点，agent 重裁过的图不再检查。检查逻辑不变，但它看到的裁图和图的处理方式都是新的；当初"严重错误 138 处全部标出"的结果，是 §10-1 要重新达到的标准，不能当作新版本已经具备的性质。
- **公式编号缺口**：改为也识别 `\tag` 里的编号。否则 agent 按 brief 补上编号后，告警依然不会消失。

### 7.4 `references/papers.md`（写给 agent 的论文指引）

按 writing-for-agents 的思路：
- `SKILL.md` 里只留一行指针，例如"文档是学术论文 → references/papers.md"，处理论文时才读；
- 内容只写论文特有、而且 agent 自己想不到的东西。

大纲：
- **读论文**：
  - 按页引用；
  - 图表编号和补充材料；
  - 跨页表格的页码；
  - 两栏页面的阅读顺序可能读串（qiu 第 5 页）；
  - arXiv 页边戳和行号稿。
- **核对论文**，示例里出现过的常见误读：
  - 模型名（`DeepSeek-RI` → `R1`）；
  - 作者行里的图标被读成希腊字母；
  - 公式编号括号变成全角；
  - 表头单元格合并（"Letter Word"）；
  - 算法框被读成表格；
  - 页末编造续句。
- **约定表的用法**：遇到新写法，比如别的期刊的图注格式，怎么补进 `conventions.py`。
