# paper-read：精读也要给项目带来启发，现在的设计没写到

- 来源：用户 · 2026-11-09，让主 agent 从各项目挑 6–8 篇重要论文精读、跑一遍流程时：
  - 「同时，你不要忘记我们精读的目的：一方面能快速了解论文；另一方面能对我们自己的项目/论文有帮助，就是能吸取什么意见，或者能参考、借鉴的学习的东西，能提供一个思路、比较前沿的概念或者灵感吧，因为有时候一些想法、灵感就是从大量的文献中出来的。就是他们可能激发我们怎么做这类的，我可能说得有点散了，你可能要整理一下我想表达的东西。这些我之前可能没太提到，但是我说的这部分还是比较重要的。」
  - 「你需要做好记录，我不太清楚你之前那个设计稿，或者我们自己已经实现的 paperread 有没有提到这些点。」
  - 随后：「另外，你就开始自己推进吧。如果对于规则层面或者 skill 层面的优化，你要记得用 design principle过一下。如果你在精读论文的过程中出现问题，你也做好记录，然后去相应的优化。你自己向前推进，开启无人值守」
- 状态：open。这次精读是收集证据，设计还没定（没拍板）。
- 参考资料（`20261109-paper-read-reading-for-project-insight-reference/`，git 不跟踪）：这次精读的运行记录 `run-log.md`，每篇的项目启发 `insights.md`。

## 用户要的是什么（整理）

精读有两个目的：

1. **快速弄懂论文**：以后任何任务要用这篇，读笔记就够，不用重读原文。
2. **给自己的项目和论文带来东西**：
   - 吸取的教训：别人踩过的坑、评审会挑的毛病；
   - 能参考、借鉴的做法：方法的某个部件、实验设计、评价方式、数据处理；
   - 思路、前沿概念和灵感：读多了才冒出来的想法，启发"我们这类问题可以怎么做"。

## 现在的设计和 skill 写到了哪里

- **目的 1 写透了。** spec [20261102-paper-read-notes-spec.md](../specs/20261102-paper-read-notes-spec.md) §1 的目标就是"agent 用到一篇论文时很快拿到对的、能核对的答案"；笔记的八问、出处、核对都为它服务。
- **目的 2 只写到"已经做了的决定"。**
  - 项目论文索引只记项目依据论文做过的决定，用了的和考虑后没用的（spec §2、`paper-read/references/notes.md` *The project's paper index*）。spec 例子里有一行"借鉴期相 token + 连续时间编码的双条件写法"，但那是已经定下要借鉴的决定。
  - 读论文的 subagent 只拿到"项目的问题"，而且按 SKILL.md 的模板只给问题本身、不给项目背景（`paper-read/SKILL.md` *Handoffs*），答案写在回报里，不进笔记（`references/reading.md`）。问题由主 agent 出，所以能得到什么启发，取决于主 agent 想到问什么。
  - 笔记 Q7"有什么可以进一步探索的点"讲的是论文本身还能往哪走，不针对哪个项目。
  - "这篇能给我们什么启发、可以借鉴什么"这类还没成为决定的东西，设计里没有落脚处：既不进笔记（笔记只写论文本身），也不进索引（索引只记决定）。

## 已经看到的后果

2026-11-06 那批 16 篇精读，主 agent 给每篇配了项目问题，回报里有不少对项目有用的发现（比如稿件的工作点在某基线论文里其实不占优、扩散项目的预训练底座论文里没有超声数据）。这些只写进了会话临时目录里的一份总结和聊天，没有进任何项目，也没有进本仓库；临时目录随时会清。

## 这次怎么收集证据

- 按现有 skill 精读，读论文的 subagent 的说明不改：只给问题，不给项目背景。
- 每篇的项目问题都朝目的 2 出：能借鉴什么、要避开什么、对项目的某个难点有什么启发。
- subagent 回来后，主 agent 自己写每篇的"对项目的启发"，记进参考资料 `insights.md`，不写进各项目的仓库。
- 记下来要回答的问题：只给问题、不给背景，subagent 的回报够不够主 agent 写出这一层？不够的话，缺的是论文细节，还是项目背景？
- 精读完把选项摆给用户，一次问一个：启发记在哪里（项目文档、主题笔记、笔记里新开一节……）、subagent 能不能看到项目背景。
