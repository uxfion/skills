## 讨论记录

4. 用户（2026-11-09，试读 han 2024 收尾时）：「你要交付的是结果，而不是你探索的中间过程。这点你后面在优化 paper reading 的时候要注意，不要把过程也加进去了。」当时两篇试读的笔记都把经过写了进去：头脑风暴前写"先发散后收敛，保留三条，被舍弃的有……"（MIRAGE 还写了草稿在 scratch 目录的哪个文件），Q6 开头写"按作者需要做的步骤把方法在脑子里重做一遍"。起因是设计稿把读的方法（先发散后收敛、和已链接笔记比对、答 Q6 前在脑子里重做一遍）也写进了"读的顺序"，读论文的 subagent 就照着记了下来。主 agent 存 han 2024 前删掉了这两处。改 skill 时：读的方法只写给读论文的 subagent 看，笔记里只放读出来的结论。用户随即补充：「但是我也不是很确定，万一是有用的那些发散。你探究了，然后跟我讨论」：被舍弃的想法本身算不算结论、要不要留，待讨论。

## 已定

1. **笔记里加一块"启发"，可以带方向。** 方向性的想法、灵感、学到的可借鉴的东西、头脑风暴，写进论文笔记，别的项目也用得上；不适合放笔记的（某个项目自己的取舍、实现细节）放进项目。笔记"只写论文本身、不写任何项目"这条规矩相应放宽。用户的 NotebookLM 提示（"在读博士生，专注模型架构与技术细节，最后深入头脑风暴，探讨灵感与启发"）作参考，不强制。

2. **Q3 的"核心机制"用领域本来的说法写。** 写清关键那一步是什么、为什么起作用（作者的理由和消融证据）、依赖哪些前提；不强求"不带领域"。用户（2026-11-09）：「为什么起作用，可以把带领域去掉，有时候有一些专业的核心机制，没有领域知识，他是想不出来的，我感觉是不用刻意去说不带领域的」
3. **代码和论文的出入按需细究，不设固定项**（用户选 A，2026-11-09）。项目要复现、要拿它对比、要在它上面做，或者论文没写的关键设置只能从代码里找时才查；查了就写清仓库、日期或版本、哪里不一样，标"论文外"。

4. **Q9 设 6 项，对应用户原话里的每一样**（用户选 A，2026-11-09）：**可借鉴**（能参考、借鉴的做法，写明搬过来的前提）、**可吸取的**（它的经验和毛病，我们怎么用上、怎么避开）、**前沿概念**、**和别的论文的联系**（它引用了、库里已有笔记的论文：机制相同、结论相反、能组合）、**思路与灵感**（方向层面的启发，不要求马上能做实验）、**头脑风暴**（围绕我们待解决的问题深入发散，留下最多 3 个具体想法，可以没有；每个写依据、怎么验证、可能败在哪）。主 agent 先提的精简版（3 项）对照原话删过了头，用户让对照原话后改成这 6 项。

5. **Q1 到 Q8 只加一项**（用户选 A，2026-11-09）：Q6 的"假设和局限"加"会在什么数据或场景下失败"。"照着论文在脑子里重新实现一遍、找隐含前提"（答 Q6 前）和"默认带着怀疑读"写进读的顺序，不设固定项。Q1 不加；Q6 不加疑点格式、"没报告/没做"、"反方论证"。"每问先写一行粗体结论"挪到 [20261103-paper-read-note-two-depths.md](20261103-paper-read-note-two-depths.md) 一起讨论。

6. **已有笔记用到时再补**（用户选 A，2026-11-09）：缺的只是 Q9 和 Q6 新加的那项，不算要整篇重读；哪个项目用到哪篇就补哪篇，对上当时待解决的问题。现在只补试读的 MIRAGE。这次 7 篇的启发留在参考资料 `insights.md`，补时当底子。

7. **试读 MIRAGE 用整篇重读**（用户：「按照你的建议来」，2026-11-09）：派新的读论文的 subagent 按新说明重读，写出的笔记先不存进 Zotero，和现有的笔记、参考资料里的启发并排对比，用户看完再定用哪份。此前定的"只补三处"是为了省 token；用户说「Token倒不是问题，主要是精读的质量，还有反思、借鉴、学习、brainstorm」。

8. **"和别的论文的联系"照已定 4，加一条可选**（用户选 B，2026-11-09）：只查这篇引用了、库里已有笔记的论文；主 agent 知道哪几篇笔记和这次待解决的问题相关时，可以在说明里点名让它对照。精读时不扫全库：只看一句话概括扫出来的多是题目相似的联系，还会分散精读的注意力；机制层面的跨论文组合，等笔记都有了"核心机制"，第二期按方向汇总时做。用户先前提醒：「我说的不一定正确，你要自己独立判断一下，灵感的话也可以从本篇论文中来的。跟我讨论一下」。

9. **"可借鉴"写成方法接口**（用户选 A，2026-11-09；Eisner）：做什么、什么时候适用、代价多大、效果取决于什么、搬过来要满足什么前提。

10. **Q6 加固定项"更好的验证"**（用户选 A，2026-11-09；Fong、Griswold）：换你会用什么实验去证明或推翻它的主要结论。对我们自己工作的教训，由 Q9"可吸取的"接过去。

11. **重要的论文查后续引用**（用户选 A，2026-11-09；Eisner 引 Delip Rao）：主 agent 在说明里标明这篇是否重要（项目要依赖它做决定、要复现、要拿它对比）；标了的，读论文的 subagent 查几篇直接检验或改进它的后续论文，看结论有没有被推翻或修正，写进 Q6"证据和范围"，标"论文外"和日期，上网照现有规矩。

12. **可复用的数据集、代码、权重并进"可借鉴"**（用户选 A，2026-11-09；Eisner）。用户：「前提这一块可以少一点约束，许可证不用考虑」：写清能拿来做什么、大致要什么就够，不考虑许可证（设计原则 §3 本来也说许可证不作为标准）。Q5 照旧只记公开没有。

13. **不加"第一遍通读时先记新概念"**（用户选 B，2026-11-09）：写 Q9 时整篇论文和前八问都在手边，先列清单不改变结果，只多一步。

14. **精读对所有文献一个流程**（用户，2026-11-09）：「我们现在这种精读都是对全部的文献来讲，不会说拿我投稿的或者什么东西作为特例对待，都是一样的流程」。不因投稿相关、作者关系（用户自己、共同作者）等单独处理或先问用户。

15. **叫"待解决的问题"，不叫"卡点"**（用户选 A，2026-11-09）：项目现在解决不了、挡着进度的问题，每条写成"问题：……；原因：……；缺什么：……"（后来加了第四栏，见已定 18），英文 open problems。用户：「我感觉这个词表达得不是很对」。试读用的五条（CEUS 三条、稿件两条）用户确认不变：「没有其他问题」。

16. **笔记只放结果，有价值的探索内容一条不丢**（用户选 B，2026-11-09，见讨论记录 4）：读的方法（先发散后收敛、和已有笔记比对、在脑子里重做一遍）写在给读论文的 subagent 的说明里，不写进笔记，笔记里也不写草稿放在哪。探索中得到的有意义的内容要留：头脑风暴最后加一项**没展开的想法**，一条一行，写想法、从本文哪里来、为什么没展开；已经并进别的项、或和已有笔记重复的不列。查过但排除的线索也连同理由写进相应的问里。用户：「有用的东西尽量保存」；「多记一点多点篇幅不是代价，重要的是有价值的内容不要丢了，还有探索的一些有意义的内容」。试读里被舍弃、又没进笔记的想法里有三条有用（参考资料 `run-log.md`）。

17. **试读通过**（用户选 A，2026-11-09）：两篇试读的启发和想法会拿去用，按设计改 skill。

18. **待解决的问题加一栏"试过什么"**（用户选 A，2026-11-10）：每条写成"问题：……；原因：……；缺什么：……；试过什么：……"，没试过写"无"，和其他几栏一样照项目记录写。试读时读论文的 subagent 不知道项目已经做过什么，有两条建议和项目现有的做法重了（细节在参考资料 `run-log.md`）。

19. **待解决的问题也可以来自当前任务；都没有时照常读**（用户选 A，2026-11-10）：来源是项目记录或当前任务（用户说的、手头的结果），照原话写，每条注明出处；出处没说的栏写"没说"，"试过什么：无"只在出处说了没试过时写。两处都没有时照常读，Q9 从论文本身出发，主 agent 在给用户的消息里说明，用户给出问题后再补。有待解决的问题时，思路与灵感也可以只从论文本身来。起因是旁支提醒：别的项目的记录里没写明问题时，Q9 会不贴项目。用户：「但是我之前不是也提到了，精读也可以针对当前论文来说的」。

## 用户要的是什么（整理）

精读有两个目的：

1. **快速弄懂论文**：以后任何任务要用这篇，读笔记就够，不用重读原文。
2. **给自己的项目和论文带来东西**（用户后来补上头脑风暴）：
   - 吸取的教训：别人踩过的坑、评审会挑的毛病；
   - 能参考、借鉴的做法：方法的某个部件、实验设计、评价方式、数据处理；
   - 思路、前沿概念和灵感：读多了才冒出来的想法，启发"我们这类问题可以怎么做"。

## 现在的设计和 skill 写到了哪里

- **目的 1 写透了。** spec [20261102-paper-read-notes-spec.md](../specs/20261102-paper-read-notes-spec.md) §1 的目标就是"agent 用到一篇论文时很快拿到对的、能核对的答案"；笔记的八问、出处、核对都为它服务。
- **目的 2 只写到"已经做了的决定"。**
  - 项目论文索引只记项目依据论文做过的决定，用了的和考虑后没用的（spec §2、`paper-read/references/notes.md` *The project's paper index*）。spec 例子里有一行"借鉴期相 token + 连续时间编码的双条件写法"，但那是已经定下要借鉴的决定。
  - 读论文的 subagent 只拿到"项目的问题"，而且按 SKILL.md 的模板只给问题本身、不给项目背景（`paper-read/SKILL.md` *Handoffs*），答案写在回报里，不进笔记（`references/reading.md`）。问题由主 agent 出，所以能得到什么启发，取决于主 agent 想到问什么。
  - 笔记 Q7"有什么可以进一步探索的点"讲的是论文本身还能往哪走，不针对哪个项目。
  - "这篇能给我们什么启发、可以借鉴什么"这类还没成为决定的东西，设计里没有落脚处：既不进笔记（笔记只写论文本身），也不进索引（索引只记决定）。

## 已经看到的后果

2026-11-06 那批 16 篇精读，主 agent 给每篇配了项目问题，回报里有不少对项目有用的发现（比如稿件的工作点在某基线论文里其实不占优、扩散项目的预训练底座论文里没有超声数据）。这些只写进了会话临时目录里的一份总结和聊天，没有进任何项目，也没有进本仓库；临时目录随时会清。

## 这次怎么收集证据

- 按现有 skill 精读，读论文的 subagent 的说明不改：只给问题，不给项目背景。
- 每篇的项目问题都朝目的 2 出：能借鉴什么、要避开什么、对项目的某个难点有什么启发。
- subagent 回来后，主 agent 自己写每篇的"对项目的启发"，记进参考资料 `insights.md`，不写进各项目的仓库。
- 记下来要回答的问题：只给问题、不给背景，subagent 的回报够不够主 agent 写出这一层？不够的话，缺的是论文细节，还是项目背景？
- 精读完把选项摆给用户，一次问一个：启发记在哪里（项目文档、主题笔记、笔记里新开一节……）、subagent 能不能看到项目背景。
