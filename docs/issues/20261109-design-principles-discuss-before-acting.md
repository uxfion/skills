# 设计原则：用户要讨论时，主 agent 却直接动手

- 来源：用户 · 2026-11-09，精读重新设计的讨论中。用户让主 agent 看一下设计草稿整体是否合适、有没有钻牛角尖的地方，主 agent 直接把草稿改了，用户读过的那版也没留下。用户：
  - 「我没有明确指令让你直接去改吧？我的指令应该是背后的潜意图，是讨论吧」
  - 「我感觉这种问题出现很多次，我都是想让你去调研，然后和我讨论的，你就直接开做了，把我的话认为是下一步的行动。实际上，我之前也说过啊，我们在点赞还是在哪里说过，我的话只是一个方向，也不一定正确，我需要的是讨论。」
- 状态：open。用户 2026-11-09 选了先只改主 agent 的记忆（选项 A）：「A 先A吧，我们主线不要断掉，后面再考虑就好。你记一笔.」规则层面的改动（选项 B）留到以后再看。

## 主 agent 当时找的原因（给以后讨论用）

1. **设计原则 §5 当天加的一句可能在推着动手**："Where a part holds and leaves nothing to decide, carry it out and say in a line why"。本意是用户让做一件事时，成立的部分不必逐条问；但它没区分"用户要我做"和"用户要我讨论"。这次主 agent 就是用这句给"直接删减草稿"找了理由。
2. **记忆里有几条偏向"做"**：比如"原则已经能定的事自己做、做完汇报，不拿去问用户"（2026-11-04）。加上当天早些时候开了无人值守，可能一直留在执行的模式里。
3. **没先判断用户这句话要的是什么**："推送""开始做"是要做；"看一下""你觉得""是否合适""梳理一下""重新设计一下"是要想、要讨论，该给调研、分析和建议，不改任何文件。

同样的问题此前在 2026-10-20、10-29、11-02 都出现过，每次都是补记忆。

## 选项（当时提出的）

- A：只改主 agent 的记忆，把"先判断是要做还是要讨论"写成醒目的一条。**（用户选了，2026-11-09 已做：记忆 `do-or-discuss`）**
- B：改设计原则 §5 那句，把"就去做"限定在用户要求做成某件事的时候；用户要看、想、设计、讨论时，只给结果和建议，什么都不改。规则层面，要按 §4 的流程给用户看原文、修改建议、中文和理由。
- C：先不改，看后面几次是否做到。
