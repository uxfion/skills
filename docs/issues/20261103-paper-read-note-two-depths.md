# paper-read：论文笔记里"大致看"和"细节"混在一起

- 来源：用户 · 2026-11-03。看过 T-CACE 的笔记之后：「另外有些细节层面的东西，用户不会去看的，我觉得可以用 toggle heading 或者 toggle list 去折叠掉，比如Q2.1 参考文献的编号和正文描述对得上吗？其实我感觉现在，我能大致看了一份，和很详细、很细节的一份混在一起了。我不知道该怎么做。你也可以新开一个issue」
- 状态：open，没讨论。和 [20261103-paper-read-note-images.md](20261103-paper-read-note-images.md)、[20261103-paper-read-note-expression.md](20261103-paper-read-note-expression.md) 是同一件事的几个方面：笔记要让人愿意读、读得快。

## 现场

T-CACE 的笔记有 19 问、359 行。用户想先大致看一遍，可是一级的回答、引文、核对类的子问题（比如 Q2.1"参考文献的编号和正文描述对得上吗？"）都排在一起，大致看的人得自己从细节里挑出要点。

## 已知的事实（2026-11-03 查）

- **折叠做不了。** Zotero 笔记编辑器没有可折叠的块，`<details>`/`<summary>` 不在它认的元素里，写进去会被丢掉（`zotero/note-editor` `src/core/schema/nodes.js` 的节点列表）。
- **Better Notes 也不行。** 它的"collapse"只是收起左边的大纲栏（`windingwind/zotero-better-notes` `src/modules/patches/noteEditor.ts`），不能折叠正文。
- **能用的是大纲。** Better Notes 的大纲栏按标题列出问题树，点一下跳到那一问。

## 可能的方向（没拍板，等讨论）

- **在一条笔记里分出前后两层**：开头一段"一页看懂"，写一句话概括、几条要点，加上关键的一两张图（接图片那张 issue），给大致看的人；后面的 8 问是细节，按需查阅。
- **每一问先写要点再展开**：每一问的回答开头两三行写结论，下面再是证据、引文和子问题。大致看时，每问只读开头。
- **核对类的子问题集中放到最后**：像 Q2.1 这种"有没有对上"的检查，挪到笔记末尾的一节，不和讲论文内容的问题排在一起。这要先想清楚：问题编号写下就不改，挪位置会不会和这条规矩冲突。
- **两条笔记**：一条概要、一条细节。这和"一篇一条论文笔记"（已定）冲突，列在这里只是为了完整。
