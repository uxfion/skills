# how-we-work：推送到用户手机的级别没有约定

- 来源 · 日期：hc_deduction 项目，2026-11-13。
- 涉及的文字：`references/unattended.md` *Notifying the user*。现在只写了「Only at the one stop. Bark ...」，POST 的字段是 `device_key`、`title`、`body`、`group`，没有级别。

## 现场

- 这一天项目里写了一个运行中可调的实验调度器。它在后端掉线、参与者被转到别的后端、后端恢复、后端起不来时，会用 Bark 推送到用户手机。推送脚本是项目里的 `infra/campaign/notify_bark.py`：读 `~/.config/bark/config.json`，POST `<bark-server>/push`，group 写项目名，从不打印设备密钥。
- 用户收到第一条推送后问：「我bark收到了一条消息，这是你发的吗」；接着说：「可以，我感觉挺好的。一些重要的通知你就推送给我」。项目把"哪些事推送"记进了自己的约定（`docs/conventions/experiments.md`）。
- 用户又问：「推送的级别有约定吗」。main agent 提了下面的分级。用户：「好像不是你这边要做的，应该在skills仓库那边做」。所以项目这边没有改级别，所有推送都是默认级别。
- 这张 issue 写完 5 分钟后（2026-11-13 20:24，北京时间），main agent 说"我来推：每项实验打完分（判据过没过），整个队列跑完"，用户改了口：「我来推：每项实验打完分（判据过没过），整个队列跑完。 这个不改[该]推送给我，只有非常紧急需要让我知道的事件才需要提醒我。」项目照这句改了约定（hc_deduction 提交 `365f6f2`）：只推后端掉线、后端起不来、停止规则叫停或大量失败、活被卡住要用户拍板；打完分、队列跑完在对话里汇报。下面分级表里 active 一行（结果出来了、队列跑完）和这句相反，定的时候以这句为准。（skills 仓库的会话 2026-11-14 补记）

## 提的分级（待定）

Bark 有一个 `level` 参数，取值 active、timeSensitive、passive、critical。取值和效果是 main agent 按对 Bark 的了解写的，定之前要对照 Bark 的文档核实。

| 级别 | 效果 | 用在哪 |
|---|---|---|
| timeSensitive | 专注模式下也提醒 | 要用户出手，或正在白白浪费算力：后端起不来、系统自己恢复不了；运行被停止规则叫停或大量失败；需要用户拍板才能往下走（含无人值守的那唯一一次停下） |
| active（默认） | 正常响铃、亮屏 | 结果出来了：打完分，事先登记的判据过没过；整个队列跑完 |
| passive | 不响铃、不亮屏，只进通知列表 | 系统已自己处理好的事：后端掉线后已转到别的后端、后端恢复、单个实验跑完 |
| critical | 静音模式下也响 | 不用 |

## 建议

1. 在 *Notifying the user* 写明：推送分级，以及哪类事件用哪一级。
2. 推送的范围不只无人值守停下时；用户在场时，重要的事也推送（用户的原话见上）。是否写进通用规则，由用户定。
3. 考虑把一个推送脚本放进 how-we-work 的 `scripts/`，各项目共用，免得每个项目各写一份。脚本读 `~/.config/bark/config.json`，接受 `--level`，不打印密钥，有 `--dry-run`。
