# paper-to-zotero：模型简称标签加前缀

> **已解决（2026-11-02）**：`paper-to-zotero/references/tagging.md` 里，模型简称改成 `aka/<名字>`；只有提出了这个模型、或业内用这个名字称呼的论文才打，可有可无，每类最多 5 个照旧。库里 417 篇的标签已经迁移并读回确认。`github`、`公开数据集` 还没归类，记在库待办（记忆 zotero-library-todo）。参考资料夹里的清单随结案删除，迁移的数目记在下文。

- 来源 · 日期：用户 · 2026-11-02。讨论 paper-read 的项目论文索引时，标题行要用模型简称（tagging.md 的"Common name"），用户问起这个标签。
- 用户原话：
  - 「另外有一个问题，就是你们那个common name要不要加一个前缀/？这样的话筛选好筛选一点，不然的话我找不到」
  - 「我们现有的所有自己打tag都是有前缀吧」
- 现状（2026-11-02 只读统计 `read_library tags`）：
  - tagging.md 的 8 个维度里，只有 Common name 不带前缀：`CycleGAN`、`Restormer`。其余 7 个都带：`method/`、`task/`、`modality/`、`organ/`、`dataset/`、`venue/`、`type/`，手打的带前缀标签共 392 个。
  - 不带前缀的手打标签有 416 个，大多是模型简称，比如 `AMIE`、`ReAct`、`ControlNet`、`CycleGAN`。也混着不属于这一类的，比如 `公开数据集`、`gCNR`、`GAN`、`CEUS LI-RADS`，像是方案出台前打的，或者打错了维度。
  - 另有 453 个不带前缀的自动标签（出版商给的关键词）。
  - 简称和这两类混在一起，所以在 Zotero 的标签栏里找不到。
- 为什么要紧：标签栏没法把模型简称单独列出来；paper-read 的项目索引标题行（论文笔记 issue 已定 39）也要从标签里取简称，不带前缀就分不出哪个标签是简称。
- 方向（没拍板）：
  - 简称改成带前缀，比如 `name/CycleGAN`。理由和 `venue/` 一样：标签栏能把所有简称一起列出来，直接打 `CycleGAN` 仍然搜得到。
  - 新打的标签先按新规矩打。
  - 已有的 416 个由 judge 分批判断：是简称的改成带前缀，不是的归到它该在的维度，或者留着不动。改动列成清单，用户确认后再写库。
- 前缀的词：
  - 我先给了 `name/` 和 `model/`，推荐 `name/`。
  - 用户：「前缀用哪个词比较好？我觉得这两个都不是很好。你看，我全部再看一遍，看有没有合适的。因为我想的是，整个学术界或者是整个社区，都普遍会叫某些论文一个名字嘛，这个缩略的名字.」
  - 我又比了几个候选（没拍板）：`aka/`、`alias/`、`abbr/`、`short/`、`nickname/`、`known-as/`；也考虑了 Zotero 自带的"简短标题"字段。比较见对话，结论等用户定。
- 用户：「A 另外可以有多个，不要把限制定死，有些论文有两个通行的名字，比如 Stable Diffusion 和 LDM」。定为 **`aka/`**，一篇可以打多个。我起初写成"不设上限"，用户纠正：「每类最多 5 个还是依旧有的，对所有的都生效」。
- 2026-11-02 改了 `paper-to-zotero/references/tagging.md`：
  - 表里的 Common name 改成 `aka/<Name>`；
  - "两个通行的名字都打"写在 Common name 一条里；上限照"每类最多 5 个"，`aka/` 也算在内；
  - "前缀让标签栏能整类列出，打不带前缀的值也搜得到"这句合并到 Prefix 一条，原来在 Venue 一条里；
  - 整理一节加了旧的不带前缀简称怎么迁移。
  - 我起初改完没让 advisor 审，用户：「改前应该让advisor审一下，然后调用writing for agents skills去修改优化」「你下次应该先 advisor 审，然后再动手，我之前也提到过」。之后补了 advisor 审查（改了四处）和 writing-for-agents，记忆已改。
  - SKILL.md、organize.md、tidy-judge.md 都没提简称标签的形式，`lint_items` 也不查标签前缀，所以不用改。

  - 2026-11-02 fork 交回清单：迁移清单（已随结案删除）。416 个，每个只归一组：

- 2026-11-02 用户（看了上面的进展后）：「论文没有提出新模型或者论文的模型的那种就不要加，只有本身提出的新模型，或者是行业通识中针对这篇文章的叫法，你就保留，不要强制加上去，你可以不加的。」
  - 规矩收紧：只有论文自己提出了带名字的模型，或者业内本来就用这个名字称呼这篇论文，才打 `aka/`；只是用到、改进或评测某个模型的论文，不打那个模型的名字。`aka/` 可有可无，不去补打。
  - tagging.md 按这句改（先给 advisor 审）。
  - 清单第 1 组（357 个）是按旧说法分的，只靠看题目挑出了 9 篇错挂的；退回同一个 fork，按新规矩逐个复查：挂这个标签的论文是不是提出了这个模型。

    - 从这篇论文上去掉 28 行；

    - 要用户定 0 行。
