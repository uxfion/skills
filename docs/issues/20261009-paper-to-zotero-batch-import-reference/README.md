# 参考代码：批量补取出版社 PDF 时的临时做法

这些脚本是一个研究项目在 2026-10-10 批量补取出版社全文时写的临时补救，不是 skill 的代码，也没有按 skill 的标准测试过。放在这里只供修改 `paper-to-zotero` 时参考，对应 issue `20261009-paper-to-zotero-batch-import.md` 的第 26、27、32、34 条。已去掉个人路径与机构信息；下载目录由环境变量 `DOWNLOADS` 给出。

| 文件 | 做什么 | 对应条目 |
|---|---|---|
| `watch_downloads.py` | 批次一开始就启动、一直运行的下载监控：Downloads 出现新的完整 PDF（不论是用户还是脚本点的），按题名匹配待取清单，过身份核对后认领、挂附件、标记完成；匹配不上的文件留在原处只记录 | 34 |
| `fetch_batch.py` | 驱动：逐条走路线（OpenReview 页面内取 → 出版社页面内取，被拒时直接打开 PDF 链接 → 机构检索系统）；每一步都可中断，监控进程完成当前条目后 1 秒内放下这一条；门禁等待最长 15 分钟 | 26、34 |
| `batchlib.py` | 两个进程共享的状态（TSV + 文件锁）、认领、挂附件，以及入库前的身份核对 `verify()`：题名实词 ≥ 80% 出现在前 3 页、第 1 页印的 DOI 必须是这一篇、不是补充材料 / 勘误 / 撤稿通知 | 32、34 |
| `fetch_browser.py` | 各条路线与门禁识别（标题关键词，含单点登录页）；被 `fetch_batch.py` 导入 | 26、27 |
| `tools/pubfetch.sh`、`tools/samefetch.sh` | 打开 `doi.org/<DOI>`，取 `citation_pdf_url` 或“Download PDF”链接，在页面内同源 fetch 成文件 | 11、22 |

没有放进来的：机构检索系统（Primo）查询与 ProQuest 取文件的两个脚本，它们写死了某个机构的地址。

已知局限：门禁识别仍只看标题关键词，没有看主机名（第 26 条的方向）；“Host Needed”（代理不覆盖该主机）与登录页要分开处理，这里是让它落到“没有 PDF 链接”、换下一条路线。
