# paper-read：对着公开代码读一篇重要论文时，带回什么

- 来源 · 日期：起草 how-we-work 的文献参考时碰到的，2026-11-10 记录。
- 状态：只记下，没有设计。

## 看到了什么

how-we-work 的文献参考里有一段"重要论文有公开代码的，对着代码读"，其中列了这次阅读要带回的东西：方法的每一块在代码的哪个文件哪一行（损失和权重、调度、预处理、训练和推理的入口）；论文没说的默认值和设置；论文和代码每一处不一样的地方；发布里缺什么（训练代码、权重、数据、配置）；我们能借什么，各标明是原样用、重新实现还是只取设置。

读论文这件事本身是 paper-read 做的。它现在的阅读说明没有"对着代码读"这一种情形：读的人拿到的任务说明里没有位置写"项目要在这篇上往下做、为什么"，也没有位置给克隆下来的仓库路径和提交号；笔记里"论文之外的来源"怎么记代码里看到的东西，没有例子。结果是这张"带回什么"的单子落在了 how-we-work 的文献参考里，而它其实是阅读的一部分。

## 为什么要紧

用户在 diffusion 项目里连着几条消息要过这种读法（原话在 how-we-work 的文献参考里引了）：

- 「特别重要的，然后也有GitHub仓库的，对照着看，同时做好research的笔记。」
- 「因为后面我们肯定要改 baseline 或者优化我们的 baseline，然后逐渐形成方法。」
- 「而是知道它的一些方法实现，然后为我们所用的，对我们完成这个任务有帮助的，可以吸收借鉴的」
- 「你如果调研的话，肯定是把这个仓库git clone克隆下来,然后再慢慢看是最方便的」

## 可以怎么处理（没拍板）

paper-read 的阅读说明里加"对着代码读"这一种：任务说明带上项目为什么要在这篇上往下做、克隆的路径和提交号；带回什么的单子搬到 paper-read；how-we-work 的文献参考只留"什么时候要这样读"和"先克隆到 `repos/`"，其余指过去。和 `20261109-paper-read-reading-for-project-insight.md` 有关（都是为项目读一篇论文时带回什么），整理 paper-read 的 issue 时一起看。
