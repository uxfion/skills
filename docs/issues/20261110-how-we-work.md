## 全局概览：这是什么，从哪读起

**这件事是什么。** 用户有好几个研究项目（hc_deduction、ceus、zym_video_3d 等），每个都要搭一层"项目之上"的东西：给 agent 的规则（`AGENTS.md`）、记忆（`.memory/`）、记录和文档放哪、实验 / 报告 / 文献 / 问题单怎么做、怎么和用户协作、无人值守怎么跑。各项目各自长出来，散在 memory、AGENTS.md、docs、spec、issue、SKILL.md 里，互相不同步。2026-11-02 在 zym 把三个仓库的这一层收拢成一套，走得很曲折。用户想以后把它做成一个通用 skill（带上必要的 memory、AGENTS.md、roles 等），新项目照着搭，不再重走。本 issue 收的是做 skill 的原料：结果、过程、用户的想法、三个起点仓库的原件。

**有三层，别混。**
- **全局指令**：所有项目都适用的个人偏好，进 `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`。归本仓库 `agent-instructions/` 和 issue `docs/issues/20260929-agent-instructions-reusable-memories.md` 管，还没定。在那之前，跨项目偏好照用户的决定写在各项目自己的 `AGENTS.md` 里（zym spec §4 第 3 条）。
- **项目上层（本 issue 要做成的 skill）**：每个项目都要的结构、规则分层、记录格式、工作约定。
- **项目自己的**：任务和诚实边界、机器上的坑、数据规矩。

## 用户的考虑（主线，原话见编号）

- 只要项目之上的一层：规则、文档、结构和更抽象的原则，加上记忆里的做法和偏好（#10）。
- 用户的话是方向，不一定准确；先判断再改，有疑问先讨论，要有独立思维（#19–20, #47）。
- 给 agent 足够的上下文，而不是过度干预（#35）。
- AGENTS.md 只放特别重要、反复提到、原则性的东西；琐碎的留在 memory，靠索引找；结构要设计好；保持精简高效（#36–41）。
- 但不能走到另一个极端：重要的、在乎的、经常提到的不丢细节，找中间的度（#43–49, #60–61）。
- 记忆长成规则：agent 自己整理、判断、提出，用户只审核，通过后进 AGENTS.md（#50–52）。
- advisor 要在动手之前审（#24–28）；规则类改动要谨慎审，普通任务不必什么都审（#29–30）。
- 交给 agent 的文字不必用中文，对话才是给用户的（#58–59）。
- 上下文太长时，先把必要的东西写进文档或 scratchpad，再压缩（#62）。

1. 目标是项目的目标。对话里定下的任务是排在最前面的那件事，不是边界；它做完、被挡住、或在等训练和 subagent 时，agent 回到项目目标上找下一件事做。

5. 研究项目里这样的事几乎总是有的，所以 agent 实际上会一直跑到用户回来或额度用完，这正是用户要的。该停下的只有一种情况：剩下的事都压在用户的一个决定上，先做了很可能白做（hc 10-29 的批量就是）；这时把各选项准备到只差用户一句话，然后停下并告诉用户。

> 无人值守时，目标是项目的目标。对话里定下的任务排第一，做到用户会去检查的终点。它做完、被挡住或在等待时不停下：从项目目标出发，挑自己能做、不挤主线、对项目最有好处的事接着做，比如后面要走的路先探、用户要做的选择先把各选项做出来比较、能解决的 issue、文献和分析。每做完一段，回头看方向对不对，再选下一件。开无人值守时，把理解的目标和打算往前做的事说回给用户。

没定的：往前做出来的东西放哪、怎么标"没经用户确认"；哪些事留给用户（第 12 题）；靠什么不无声停下（第 13 题）；额度（第 14 题）。
